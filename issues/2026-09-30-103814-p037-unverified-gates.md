# P037's host run and Linux gates have not run

- Severity: Medium. The fresh VPS install guide and `deploy-release bootstrap` reach `main` without a run on a real host, so a step that only a real VPS exercises could stop the owner's first installation partway.
- Owner: Awaiting owner selection in this inbox. The owner's first run of the [fresh VPS install guide](../docs/developer/fresh-vps-install.md) supplies P037-07. [P026](../design/proposals/026-continuous-integration.md), still a Draft, plans hosted CI that could run the Linux lanes.
- Status: Open. Recorded on 30 September 2026, while P037 was checked in a cloud session.
- Recorded: 30 September 2026.
- Related: [P037](../design/proposals/037-fresh-vps-install-guide.md), acceptance IDs P037-03, P037-04 and P037-07, and the [P035 gates issue](2026-09-30-040032-p035-unverified-gates.md), which covers the same Linux lanes for P035.

## Problem

P037 was implemented and checked in a Claude Code cloud container: Ubuntu 24.04.4 running as root, cgroup v1, no systemd as PID 1, no Docker daemon, no SSH client and no macOS. These checks need what that container lacks, so they have not run:

- **P037-07, the guide on the VPS.** Nobody has yet run the guide from step 1 to step 16 on the emptied VPS, including the owner's browser checks.
- **The unprivileged build.** `bootstrap` builds in a transient `systemd-run` unit with `DynamicUser=yes`, as `build` does. The P037-03 build ran the same script with `sh` in place of that unit, as root and with the container's proxy variables.
- **Real-stack E2E and the personal VPS Linux lanes.** `pnpm test:e2e` needs a Docker engine. `node --import tsx tests/personal-vps/e2e.ts` and its `--concurrency` form need root on a host with systemd and delegated cgroup v2.
- **Guide blocks run only against stand-ins.** After review round 1, the P037-04 harness ran 40 of the guide's 42 Bash blocks whole, with host paths moved under a scratch directory and fakes for `ssh`, `scp`, `docker`, `systemctl`, `apt-get`, `curl` and the other host commands. Step 7's block 2, which sets the ACLs, and step 10's `install` were checked only for syntax and strings. P037's review records say how each block was checked. Traefik's certificates, `docker pull`, `apt`, `useradd`, `runuser`, the ACLs, `LoadCredential`, `install`, `login`, the first start and the live checks are unexercised.
- **The owner's computer.** The blocks that run on the owner's computer ran only on Linux, with Bash 5.2 and GNU tools, not on macOS with Bash 3.2.

## Impact

P037 stays Accepted, and its closing record stays pending, until the first host run passes. The guide stops at every failed check and every output it does not expect, so a wrong step stops the run instead of changing the host further. An installation that stops partway can still leave state that the owner must inspect, as the guide's Recovery section describes.

## Recheck

1. The owner, or an agent the owner runs, follows the [fresh VPS install guide](../docs/developer/fresh-vps-install.md) from `main` on the emptied VPS, and shares the summary that step 16 writes.
2. Record in P037's plan: the revision, the release and manifest identities, the step log with secrets removed, any stop and how it was resolved, and the owner's browser checks.
3. On a supported Linux host with a Docker engine, systemd and delegated cgroup v2, run the critical `pnpm test:e2e` suite and the personal VPS lanes, as the [P035 gates issue](2026-09-30-040032-p035-unverified-gates.md) describes.

When the host run passes, P037 can become Implemented, as its plan says. When the Linux lanes have also passed, this record can be archived.
