## Evidence and impact — 13 September 2026

A bounded source trace after diagnostic controller `4eac666` confirmed that the client discarded the broker's strictly bounded exception-class frame when its process exited nonzero. The final log read therefore lost useful failure classification. A separate source-proven boundary mismatch allowed two MiB of raw log bytes to expand to twelve MiB of escaped JSON string content, while the client capped the entire response at exactly twelve MiB. The object envelope made a valid maximum-size response exceed that limit.

Two actual C guest builds from candidate capture `23d87d4f59e0fde6ac1ddb8ac9122ab0235dcd2735f30ee69ce3960307eae603` exited 1 after successful upload. The first component omitted log collection before cleanup; the second attempted it but failed before publishing the private log. These observations do not establish either build's cause or the second log read's cause. In particular, later guardian `PIPE_CLOSED` evidence belongs to cleanup and does not prove an earlier lease failure. Both attempts confirmed exact worker/allocation retirement. No artifact, independent verifier, trusted report or stable UI acceptance passed.

## Isolated correction and review

Checkpoint `4f69765a6bf90f34c45cbf4d394f8721c03c9f6c` retains only fixed safe labels from strictly shaped broker failure frames. Controller failures settle promptly with their own bounded cause. The log wire ceiling now includes a fixed 4,096-byte envelope allowance; the raw two-MiB log limit and decoded text bounds remain enforced. Logs retain `untrusted:true` and gain no report authority. The component records final-log-read failure separately from an already completed guest command.

Node 24.11.1 subprocess contracts passed 4/4; actual Python broker routing/serialization and exchange-pump contracts passed 2/2, substituting only the Docker/identity boundary with a benign process. They cover nonzero and malformed responses, maximum escaped and replacement-character output, one excess byte, and deadline/abort with exact child death. TypeScript checking passed. The [diagnostics report](../docs/reports/2026-09-13-p010-command-diagnostics.md) records commands, environment, exact retained log hashes and the failed C attempt receipt.

Independent correction review matched both logs to the report, inspected the production observer and bounded protocol, and closed with no actionable finding. The reviewer did not rerun the checks or a guest. Actual use of the corrected diagnostics, complete candidate acceptance and main integration remain pending, so this issue stays In progress.
