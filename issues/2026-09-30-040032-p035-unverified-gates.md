# P035's Docker and personal launch gates have not run

- Severity: Medium. The disk fix reaches `main` without three of its mandatory checks, so a regression that only they would catch could reach the next installation.
- Owner: Awaiting owner selection in this inbox. [P026](../design/proposals/026-continuous-integration.md), still a Draft, plans hosted CI that could run part of it.
- Status: Open. Recorded on 30 September 2026, when P035 was delivered from a cloud session.
- Recorded: 30 September 2026.
- Related: [P035](../design/proposals/035-bounded-disk-use.md), acceptance IDs P035-01 and P035-10.

## Problem

P035 was implemented and verified in a Claude Code cloud container: Ubuntu 24.04.4 running as root, cgroup v1, no systemd, and no Docker daemon running. Three of its mandatory checks need what that container lacks, so they did not run:

- **Real-stack E2E.** The critical `pnpm test:e2e` suite starts PostgreSQL and Caddy with Docker Compose. No daemon ran, and auto mode blocked an attempt to start one with isolation-weakening flags; no default daemon was tried.
- **Personal VPS Linux lanes.** `node --import tsx tests/personal-vps/e2e.ts` and its `--concurrency` form need root on a Linux host with systemd and delegated cgroup v2.
- **P035-01.** The guardian launch contract in `tests/contract/local-runtime.test.ts` needs a personal launch, which works on macOS or on Linux with delegated cgroups. In the container, the test that holds it stops earlier with "Personal cgroup delegation unavailable", a failure it already had before P035.

Everything else in P035's gate ran there; P035's review and findings section records the results.

## Impact

P035 stays Accepted, and its closing record stays pending, until these checks pass. Its runtime change is small: every personal runtime gets `-c features.plugins=false`, and the discovery schedule changes. The unexercised risks are a personal launch that fails with the new arguments on a supported host, and an end-to-end flow that depends on the old per-tick discovery.

## Recheck

On a supported Linux host with a Docker engine, systemd and delegated cgroup v2, or on macOS for P035-01 alone, at the commit that delivered P035 to `main`:

1. Run the critical `pnpm test:e2e` suite, as the [developer guide](../docs/developer/development.md#end-to-end-verification) describes.
2. Run `node --import tsx tests/personal-vps/e2e.ts` and `node --import tsx tests/personal-vps/e2e.ts --concurrency` as root.
3. Run `HARBOR_LOCAL_CONTRACT_BINARY=<pinned Codex 0.153.4 binary> pnpm test:contract` and confirm that the personal launch contracts pass, including the P035-01 assertion that the guardian starts the binary with exactly `PERSONAL_RUNTIME_ARGS`.

Record the source identity, host, commands, exit codes and results in P035's closing record. When all three pass, P035 can become Implemented and this record can be archived.
