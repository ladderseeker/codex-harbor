The owned Linux B installation used immutable artifact `8c11ca945b654d27fe1f787db0ef5b56ce3d269a88fe3883167d3820c8848f22`, source `f13afc57f3956a7b457e567da02f1bb00ad214405c52c7a3d28f2d5c94ad1d27` /961 files. `drain --interrupt` exited 0 and retired the exact terminal. Startup timing is a supported lead, not proof of the historical timing. No unsafe listener was observed.

## Impact and required correction

An operator receives a failed command while admission has been released and the service subsequently becomes ready. Preserve maintenance through bounded startup/readiness, release admission only after readiness, and return freshly read state. Failure must preserve or restore maintenance; if that state cannot be confirmed, stop the exact API/supervisor roles. Keep restored-instance activation requirements and identity/confinement checks intact.

The correction is isolated from P010 work. Verify delayed startup, deadline failure, already-running retry, post-release status failure and database-loss behavior, then independently review the change and actual Linux command outcome. Use only the designated disposable installation and restore its prior drained state. No protected backup, transfer or promotion is needed for this bounded fix.
