# Resume reports failure after releasing maintenance

- Severity: Medium
- Status: In progress
- Owner: P009 implementer; independent module reviewer
- Affected files: `infra/deploy/harborctl`, readiness invocation and deployment command tests
- Acceptance: [P009-01/02/03](../design/proposals/009-portable-deployment-and-restore.md#independent-acceptance), administrator recovery

## Evidence — 8 September 2026

The owned Linux B installation used immutable artifact `8c11ca945b654d27fe1f787db0ef5b56ce3d269a88fe3883167d3820c8848f22`, source `f13afc57f3956a7b457e567da02f1bb00ad214405c52c7a3d28f2d5c94ad1d27` /961 files. `drain --interrupt` exited 0 and retired the exact terminal. Immediate `resume` exited 1 with `Private listener confinement failed`. A later read-only packaged status exited 0 with all four roles active, readiness ready and maintenance false. The later status is not a successful resume result.

The owned control evidence is retained as `tools-identity/pre-external-drain.log`, `pre-external-resume.log` and `post-resume-status.json`. Source inspection shows resume clearing maintenance, starting services and immediately invoking one-shot readiness. The units use `Type=simple`; an earlier suggestion of `Type=exec` was retracted. Startup timing is a supported lead, not proof of the historical timing. No unsafe listener was observed.

## Impact and required correction

An operator receives a failed command while admission has been released and the service subsequently becomes ready. Preserve maintenance through bounded startup/readiness, release admission only after readiness, and return freshly read state. Failure must preserve or restore maintenance; if that state cannot be confirmed, stop the exact API/supervisor roles. Keep restored-instance activation requirements and identity/confinement checks intact.

The correction is isolated from P010 work. Verify delayed startup, deadline failure, already-running retry, post-release status failure and database-loss behavior, then independently review the change and actual Linux command outcome. Use only the designated disposable installation and restore its prior drained state. No protected backup, transfer or promotion is needed for this bounded fix.
