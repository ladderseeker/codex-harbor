# Preview development and installation

P011 is in progress. Its current implementation and evidence are recorded in the [development report](../reports/2026-09-08-p011-development.md); the [user guide](../user/previews.md) describes the interface. Full source review, corrective local/Linux lifecycle and cumulative critical checks passed. Main acceptance, fresh-host and protected-transfer gates remain explicit.

The API owns preview metadata, scoped PAT management, owner-browser opening tickets and the separate HTTP gateway. The supervisor owns native execution, exact writer/reader reservations and the private relay broker. Codex protocol calls remain behind the adapter. Preview-purpose transports accept the fixed non-PTY package command and zero-byte identity probes, with no conversation, model or account mutation capability.

On supported Linux, the fixed relay container joins only the exact preview runner's network namespace. It mounts no checkout, credential, host socket or Docker socket. The runner uses the outer Docker/XFS boundary with no network egress and the unchanged base seccomp policy. Project scripts run through the pinned npm executable; native nested sandbox creation is not enabled for previews. The selected profile determines physical checkout/common read-only or write mounts.

An installed configuration may include `previews` with exactly `domain`, `port`, `certificate`, and `key`. `domain` is the separate canonical DNS suffix; `port` is a distinct private gateway listener. The certificate and private key are administrator-controlled files for the wildcard preview origin. Installed Caddy serves wildcard HTTPS on 443 and forwards to that fixed private listener. Provision DNS and valid wildcard TLS separately; the configuration does not create DNS records. The package records the exact `previewRelay` image. Omission disables preview admission.

The API and supervisor receive `HARBOR_PREVIEW_DOMAIN`, `HARBOR_PREVIEW_PORT`, `HARBOR_PREVIEW_HTTPS_PORT`, and `HARBOR_PREVIEW_SOCKET` through the installed service configuration. Browser clients never select a host socket or relay destination. Only the trusted bootstrap document uses the narrow origin referrer policy needed for the cross-origin form; project pages and landing pages retain no-referrer behavior, and exchange rejects null or foreign Origin.

Run `pnpm test:e2e --previews` for the real UI/API/PostgreSQL/supervisor/gateway lane with fixture external boundaries on macOS. `node --import tsx --test tests/contract/preview.test.ts tests/previews/relay.test.ts` covers the fixed adapter protocol and actual local streaming relay. `node --import tsx --test tests/previews/migration.test.ts` checks a fresh database and the exact earlier migration set where 016 precedes 014. Follow the [Linux workflow](linux-verification.md) for root-owned fresh XFS namespaces; set `HARBOR_TEST_XFS_MOUNT` and `HARBOR_TEST_CONTROL_ROOT` only to a dedicated verification unit. That lane uses the pinned actual runtime and physical helper/relay boundaries. Never point it at a personal project or installation data.

Preview metadata, bounded logs and historical native references are registered with deployment inventory. Maintenance freezes new starts; explicit interruption drains accepted execution before services stop. Restore invalidates viewers and old generations, preserves historical references, and never replays a package script. `harborctl recover-runtime` supports the exact preview runtime identity after services stop and requires the existing explicit acknowledgement and lock-inode checks. The local metadata-clone test is not a filesystem or off-host restore test.

Retain separate source/artifact identities for application tests, installed releases and later test-only changes. The recovered 8 September artifact is historical evidence; the 13 September recovery did not modify it or reuse its fixture for new acceptance.
