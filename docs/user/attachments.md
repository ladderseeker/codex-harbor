# Attachments and saved drafts

## Design and evidence ownership — 20 September 2026

[Current subsystem designs](../../design/systems/) own behavior and limits; the [issue inbox](../../issues/) owns unfinished acceptance. Historical proposal IDs below identify feature lineage and evidence, not active execution. Future changes follow a newly selected proposal under the [workflow](../../design/workflow.md); baseline reconciliation did not rerun application gates.

Use the plus button (**Attach file**) to choose files, drop them anywhere in the composer, or paste an image or files into the message box. Clipboard files must be exposed by your browser and operating system; use the picker when paste is unavailable. Ordinary text paste still inserts text. Selected files appear with your draft. Harbor saves the message and selection for 24 hours; wait for **Draft saved for 24 hours** before closing the page.

PNG and JPEG images are normalized for native image input, including orientation and metadata removal. Images are limited to 16 million pixels and 8192 pixels per side; malformed, animated or multipage images are rejected. Other files, including documents, code and archives, are passed as file paths for Codex's tools to read. Harbor does not automatically convert documents or extract archives, and readability depends on the available tools and model.

Each file may be up to 10 MiB, including its normalized image content. A message accepts up to four files totaling 20 MiB, with or without accompanying text. A conversation retains at most 32 attachment records and reserves 100 MiB; the instance reserves 500 MiB. Deleted and expired records may count until bounded cleanup completes. Upload rejection explains the applicable limit.

The selected model must advertise the appropriate text or image input. If it does not, select a compatible model or remove the unsupported file. Wait for uploads to finish before sending. While Harbor saves and sends a message, its text and attachment controls are disabled. Uploading alone does not send a file to Codex: **Send** associates the selected files with that message. Personal attachments live in private Harbor state outside the project directory. Submitted files remain visible with their original message after reload. Use **Download** to retrieve a file; PNG/JPEG previews use normalized images with metadata stripped. Names are display labels and do not select server paths.

**Pause upload** stops the current upload attempt, including preparation before the binary transfer. **Retry upload** continues using the same file identity. After reloading an incomplete upload, choose the same file again. Harbor verifies its size and hash, so different bytes cannot replace that upload. If the message response is lost, use **Retry same request** to recover the accepted result without sending another turn. If the message is accepted but the saved draft cannot reload, the submitted files leave the composer and Harbor shows **Reload saved draft**. That reload preserves a newer draft saved in another tab.

**Remove** discards an unsubmitted file and removes it from the saved selection. Submitted attachments remain with their conversation and cannot be removed through the staging controls. Expired, unreferenced uploads are collected; a fresh draft protects its selected files from collection. Draft revisions detect edits from another tab, and sending an older saved draft does not erase a newer one. If a draft conflict is shown, reload the saved draft before editing again.

Attachment routes require the browser owner's authenticated session. API tokens do not grant attachment upload, download or draft access. Avoid putting credentials in messages or files; use the protected account setup controls.
