## Review and interruption evidence

Round 1 found incomplete private-response handling, unsafe reconciliation after partial deletion, and unbounded failed DELETE attempts. Corrections bound the request lifetime, retain exact authorized removal state and reuse bounded operation/receipt identities. Actual truncated/slow replies, worker death and partial removal tests passed.

Round 2 found project changes could lag a completed receipt on the separate control filesystem. The final correction flushes project effects before publishing receipt completion. An applied creation must also match its recorded identity and bounded full-content fingerprints before retry can settle; applied removal resumes exact idempotent cleanup. Error, timeout or mismatch remains pending without copying newer source. The reviewer closed the corrected scope with no remaining actionable critical finding.

Linux tests inject actual `syncfs` failure, restart the owned service, change an applied checkout and prove that flushing alone cannot publish invalid content. Restoring the fixture's original bytes permits exact same-inode completion. These tests establish error/replay ordering, not physical power-cut behavior.
