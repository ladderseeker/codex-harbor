## Projects and workspaces

Project management and the sidebar organize registered projects and conversations. Register or create folders beneath configured allowed roots, choose Local or Git Worktree mode, show the selected branch/revision/path identity, and run independent conversations concurrently. Support a bounded explicit copy option for non-Git projects. A deleted/renamed/unavailable folder produces a recoverable state rather than silently switching a conversation to another path.

Project and workspace administration, including workspace creation, archival, removal and uncertain-reservation release, requires current owner-browser authority; PATs do not grant these management routes. Token-exposed conversation and resource operations require an explicitly allowlisted route, current authority, the operation's scopes, project grants and applicable permission ceiling. The implemented [file and Git controls](#files-and-git-review) and [persistent terminals](#persistent-terminals) share workspace admission and their separately defined authorization. PR service integration remains excluded.

[D005](../decisions/005-managed-project-workspaces.md) records the managed Git metadata, fixed helper, quota and workspace admission contract.

Persist stable project/workspace IDs, registered canonical roots, workspace type, base revision, native path mapping, ownership, and lifecycle. Enforce per-project runner mounts and resource budgets. Worktrees provide separate checkouts while sharing repository metadata; they are not a security boundary. Show how uncommitted source changes are handled before workspace creation. Do not delete dirty worktrees automatically.

Admission coordination is per workspace across managed runs and delivered editor/Git/terminal clients. Serialize conflicting managed writers; permit parallel work in separate workspaces. This is cooperative coordination, not a guarantee against arbitrary scripts or external SSH writes. Resource removal rechecks active leases and background work. Project archival never implies permission to delete source folders.

The D005 owner-browser release command requires explicit unknown-effects acknowledgement and expected session/generation. Acceptance includes stale release rejection, denied authority, failed retirement retaining ownership, and successful reuse by another conversation through the real UI/API. Original uncertain work is preserved without replay.

The fixed managed workspace authority remains [D005](../decisions/005-managed-project-workspaces.md), with D002 registered ancestry and D003 complete XFS quota units. Imported common Git metadata and checkout identities are validated together; Local `.git` publication and derived common-store publication are distinct. Archive never deletes owner source, and dirty/active/uncertain resources cannot be removed automatically. Shared typed writer reservations and project metadata exclusion coordinate every delivered client; read-only previews hold generation-bound readers. External SSH/scripts are outside cooperative writer coordination.

### Personal shared conversation membership

[D014](../decisions/014-personal-conversation-concurrency.md) permits multiple personal local/VPS conversations on the same registered canonical workspace. Membership is durable and generation-bound, independent of the managed exclusive writer fields. The owner coordinates writes; local remains read-only. Admission grants no additional paths or permissions. Project/workspace archival, removal and storage operations check all members, including startup, retained, retiring and unknown generations. Confirmed retirement removes only the exact member; ambiguity blocks that conversation and consumes capacity without blocking unrelated personal members beyond configured limits. Managed file/Git, terminal and preview reservations and recovery retain their existing exclusion.

## Files and Git review

The project workspace selector opens **Files** and **Changes** for an explicit workspace ID. The visible workspace name/kind and busy/uncertain state remain present beside file paths and Git actions. A lazy directory tree, filename/text search, editor, and change list share this selection. Changing workspaces or closing a dirty editor requires an explicit keep-draft/discard choice; saving never stages anything. Renamed/deleted files leave the draft available with a conflict explanation and a deliberate reload/reapply action. There is no force-save toggle that bypasses revision checking.

Use the direct `monaco-editor` package pinned to **0.56.0**, lazy-loaded from authenticated, locally built assets, without a React wrapper or CDN dependency. Use standalone text and diff editors with one bounded model per open file, dispose models/workers on close, and bundle the editor worker through the existing Vite build. Enable accessible labels, automatic layout and keyboard navigation; keep application controls usable on narrow viewports with a single-pane diff option. Disable clickable content links, rich/untrusted hover providers, external schema fetches, project extension loading and automatic formatting. Syntax coloring is presentation only. Full language services remain excluded. [Pinned Microsoft release](https://github.com/microsoft/monaco-editor/releases/tag/v0.56.0), [upstream integration/model guidance](https://github.com/microsoft/monaco-editor/blob/v0.56.0/README.md), [editor options](https://microsoft.github.io/monaco-editor/typedoc/interfaces/editor_editor_api.editor.IStandaloneEditorConstructionOptions.html)

Drafts remain in browser memory by default, never operational logs or persistent browser storage. An API or supervisor restart preserves the open tab and its draft. A browser reload warns about unsaved work; it does not promise recovery of text never saved to Harbor. A lost save response retains the same operation/key and draft until reconciliation, so an uncertain request never silently becomes a new save.

### Public read and invalidation contracts

All routes are under `/api/v1/workspaces/{id}` and resolve the registered workspace and its project before any content or receipt is disclosed. Versioned OpenAPI declares exact route descriptors rather than a permissive prefix. Browser mutations retain Origin/CSRF and current pinned owner checks. The explicit token scope vocabulary includes `files:read`, `files:write`, `git:read`, `git:write`; tokens also require the selected project grant. Both write scopes require the effective workspace-write ceiling. Existing tokens gain no new scopes automatically. File/Git scopes never imply credentials, raw runtime or host administration access. Cookie-free authenticated downloads use an Authorization header through fetch; no token appears in a URL.

| Route                                         | Result or accepted intent                                                                                                  |
| --- | --- |
| `GET /files/tree?ref=&cursor=&limit=`        | One directory page, entry kind/opaque reference, bounded display path, directory revision and explicit truncation          |
| `GET /files/search?q=&mode=filename%7Ctext&cursor=` | Literal query results, relative path, bounded line/snippet for text mode, scan/truncation budget and filter-bound cursor |
| `GET /files/content?ref=`                     | UTF-8 text or an explicit binary/oversized/unavailable reason, exact byte revision and file metadata                       |
| `GET /files/download?ref=&revision=`          | Authorized attachment download of the exact inspected revision; changed content returns conflict                           |
| `POST /files/save`                            | `{ref, expectedRevision, text}` with Idempotency-Key; durable operation ID/result                                          |
| `GET /git/status?cursor=`                     | HEAD/ref identity, staged/unstaged/untracked/conflict entries, index revision and bounded page                             |
| `GET /git/diff?ref=&side=staged%7Cunstaged` | Exact old/new blob identities and modes, bounded diff and selectable server-derived hunk IDs |
| `POST /git/stage`, `POST /git/unstage`        | Exact reviewed selection, expected HEAD/index/file revisions and Idempotency-Key                                           |
| `POST /git/commit`                            | Reviewed staged-tree identity, exact selected entries/hunks, expected HEAD/ref/index, explicit message and Idempotency-Key |
| `GET /file-operations/{operationId}`          | Scoped queued/running/succeeded/failed/uncertain result, identities and safe reason; no raw helper log                     |
| `POST /file-operations/{operationId}/inspect` | Explicit bounded exact-helper retirement and read-only effect inspection, expected reservation epoch and Idempotency-Key   |
| `POST /file-operations/{operationId}/release` | Consume a confirmed inspection with explicit unknown-effects acknowledgement; release only its typed ownership CAS         |
| `GET /files/events?cursor=`                   | Authorized bounded invalidation stream with workspace revision and resync marker                                           |

Opaque references encode or map exact relative filename bytes and are bound to workspace identity; they are not filesystem authority. Unicode and hostile names remain navigable without treating display strings as shell syntax. Reject NUL, absolute paths, parent traversal, ambiguous separators, excessive depth and paths into Git administrative/control locations. Symlinks appear as non-traversable entries; neither reads nor writes follow them. Invalid-UTF-8 names receive an escaped display label and opaque reference, not lossy round-tripping. Missing/renamed identity returns a bounded not-found/conflict response without an outside-path diagnostic.

Limits are 1 MiB UTF-8 per editor model/save, 4 open models, 16 MiB per download, 200 directory/status entries per page, path depth 32 and 4 KiB encoded path. Search is literal, 1–120 characters, at most 10,000 visited entries/32 MiB inspected text/2 seconds and 200 matches per response; files above 1 MiB are reported as skipped. A signed cursor carries scope/query/directory revision and remaining finite scan budget, expires after five minutes, and cannot turn a bounded query into an unlimited recursive scan. Hidden ordinary files remain discoverable; `.git`, native homes, Harbor staging and other control metadata are always excluded. Git status scans at most 10,000 paths, with an explicit incomplete result; incomplete selection cannot authorize a commit. Diffs are capped at 1 MiB/2,000 hunks/20,000 lines per file and 100 selected paths/2 MiB total selection per mutation. Binary/oversized entries show status and exact identity, support a bounded download where eligible and whole-file selection where the complete byte/object identity is available; they never masquerade as an empty text diff. An exceeded complete-review budget rejects mutation with a named limit.

Watch only the selected workspace's expanded directories/open files, at most 32 directories and four file content revisions per client, with a two-second coalescing interval and no repository-wide recursive watcher. Polling is an acceptable portable backend under those bounds. Notifications invalidate views; they do not replace drafts or claim a lossless audit of external shell writes. At most four streams per actor and 1,000 retained invalidations per workspace for one hour; a missing cursor/gap requires rereading the bounded view. Resync also follows API restart. Every stream and download rechecks current authority; downloads stop on disconnect/revocation, have a 30-second deadline, `attachment` disposition, safe encoded filename, `application/octet-stream`, `nosniff` and `no-store`. HTML/SVG never render on the application origin.
### File revision, admission and durable saves

A file revision binds the workspace identity epoch, exact relative reference, regular-file device/inode, mode and SHA-256 of its exact bytes, with an explicit absent-file marker where creation is supported. Reads use descriptor-relative no-follow opens, require a regular single-link file, and compare metadata before/after hashing. Deny hard-linked editable files rather than allowing an unseen alias to be changed. Preserve UTF-8 bytes, BOM and line endings unless the user explicitly edits them; a no-op save is not a newline conversion. Git administrative files cannot be edited through this route.

A managed save first accepts a durable bounded operation in PostgreSQL, including the expected revision and immutable new-content digest. Its bounded payload is kept only while needed to complete/reconcile that operation, not as a duplicate repository history. The supervisor acquires the same workspace writer exclusion as P003; an active or uncertain runner, unresolved helper, storage operation or recovery holds the workspace busy. Saves never race a Harbor agent writer by merely comparing an earlier hash. Reads may run during a writer, but return an observed revision and honest changed-during-read failure, not a consistency guarantee over an entire tree.

Lock order is current authority/instance gate, project metadata reservation where required, workspace, then related session/operation. Use the shared lock-then-current-clock authority helper after waits and immediately before accepting the fixed effect grant. Expired/revoked callers cannot start a queued save/Git command. A command whose effect grant and private receipt are already committed may finish/reconcile that exact effect after logout; this does not grant any new command or runtime send. Maintenance freezes new file/Git admission and drains accepted effects under D006.

Inside the confined helper, open the validated checkout root and all ancestors by directory descriptors without following links. Recheck the expected target revision after all admission waits, create an exclusive same-directory temporary regular file with safe preserved mode, write and fsync, revalidate the target, then atomically replace it through the held parent descriptor and fsync the directory. Never edit in place or truncate before checking. Parent/target swaps fail or remain confined to the owned descriptor subtree; they cannot redirect access to the host. Arbitrary out-of-band SSH/root writes are outside Harbor reservations: detect observable changes and report them, but do not claim compare-and-swap against an uncooperative external writer that changes the file between the final check and rename. The actual Linux tests must establish confinement separately from managed-client revision serialization.

A trusted receipt outside project roots binds operation ID, actor grant, workspace epoch, expected revision and new digest before the first effect. Record prepared/applied/completed phases and resulting identity, flush the project filesystem before publishing completion on the control filesystem, and follow D005's exact-helper retirement rule. Response/DB commit loss returns the same recorded result. If a crash leaves effect ambiguity, inspect only the recorded destination and owned staging after confirmed helper retirement: an authenticated applied receipt identifies the intended result but is not proof that the effect survived a crash. Revalidate the exact recorded file identity/content and complete the project flush before publishing completion; mismatch stays uncertain without replay. A completed post-barrier receipt can reconcile the original success despite a later external change. Unproven content coincidence does not justify another write. Mark uncertain and retain the writer reservation until explicit inspection/acknowledgement, with no automatic overwrite replay. The retained operation is readable after API restart.

### Exact Git selection and publication

A status/diff review token binds the registered checkout/common identities, HEAD symbolic target and object ID (or unborn marker), complete index digest/tree and exact old/new path/blob/mode identities. Server-derived hunk IDs hash that versioned diff plus hunk offsets/content. Stage/unstage accepts only IDs from the reviewed generation; no client-supplied patch, revision expression, refspec, arbitrary Git option or shell command is accepted. Recompute the selected diff under reservation before applying. A changed index, HEAD, selected file, rename pair or hunk returns 409 and preserves the UI selection/draft for explicit refresh; do not silently widen to all changes.

Stage applies selected unstaged whole files or text hunks to the index only. Unstage applies selected staged whole files or hunks toward HEAD in the index only, preserving worktree bytes. The UI distinguishes staged and unstaged sides and shows excluded changes. Rename pairs, binary data and mode changes are indivisible whole-file selections; conflicted index entries are visible but cannot be staged/committed through this feature until deliberately resolved externally. Use a private temporary index constructed from the validated current index and exact server-generated patch/blob updates, then validate the result tree. Git's own index lock plus the Harbor workspace/project reservation prevents other managed publishers; stale external index changes reject before publication. Never call reset/checkout/clean as a substitute for unstage. [Git apply index semantics](https://git-scm.com/docs/git-apply)

Commit previews the complete staged tree and its difference from the expected parent, including selected hunks. It commits exactly that reviewed staged tree: if unrelated staged entries exist, the owner must include them explicitly in the complete review or unstage them first. No implicit `-a`, hidden staging, amend, merge, signing, push or remote action occurs. A partially staged file retains its unstaged changes. Require a nonempty message up to 8 KiB and configured validated author name/email; show the identity before acceptance. Do not import untrusted repository identity or executable signing configuration. Unborn HEAD is supported with a no-parent tree and explicit absent-ref expectation; detached HEAD is visibly identified and uses an exact HEAD publication target.

The confined helper creates the exact commit object from the reviewed tree, parent, message, identity and acceptance timestamp fixed in the durable intent. Persist the resulting commit OID in the trusted receipt before advancing the branch/HEAD. Publication uses a fixed validated ref and old-OID comparison, retaining the branch identity check; do not accept a ref supplied by the browser. Reconciliation checks the recorded object and exact ref result after confirmed helper retirement. A receipt proving publication returns the original OID even if a later external change moved the branch; otherwise conflicting/unknown publication stays uncertain and never creates another commit or resets the ref. Git objects, index/ref durability and project flush must complete before the external completion receipt. An applied Git receipt predates the final project barrier: revalidate the recorded index, ref and required tree/commit/blob objects, then flush successfully before promoting it to completed. If recorded applied state is missing or conflicts, retain uncertainty without replaying an index/ref write; only a completed post-barrier receipt proves the original success independently of later edits. Interrupted stage/unstage similarly reconcile the recorded old/new index digest, never reapply an uncertain patch. [Git commit-tree](https://git-scm.com/docs/git-commit-tree), [old-value ref update](https://git-scm.com/docs/git-update-ref)

Local Git publication uses the Local checkout's authoritative in-checkout `.git` index, objects and refs. the workspace service’s imported project `git-common` is an independent store and is never a substitute target for a Local stage/commit. The confined helper reaches Local metadata through no-follow descriptor-relative authority within the validated checkout and its sanitized metadata view; a repository-controlled `.git` pathname is never elevated into host bind-mount authority. Derived Git workspaces instead publish through the registered common repository and their validated workspace administrative IDs. Status/diff/review tokens explicitly bind which of these stores is authoritative, preventing cross-store index/ref publication. Unsupported external Local gitdir/commondir mappings fail closed under D005.

All Git operations remain inside D005's fixed nonroot, network-disabled helper with immutable entrypoint, resource limits and selected checkout/common mounts. Extend its action enum and protocol; do not add a generic exec route or host Git call. Disable hooks, filters, textconv, fsmonitor, external diff, pagers, automatic maintenance, signing, credential helpers and all network protocols. Local/common configuration is never executed or imported into the sanitized metadata view. Git hooks are not run by this managed profile, and the commit UI states that fact; a future hook-execution feature would need an explicit confined execution contract. Raw objects are hashed/staged without project clean/smudge filters, with that managed-profile limitation visible. Unsupported alternate/object/gitdir/submodule configurations fail closed rather than expanding mount access.

Any mutation of shared common Git metadata holds the workspace service’s project metadata exclusion in addition to its workspace writer reservation, and conflicts with existing managed writers that can access that common store. This may serialize Git publication across otherwise independent worktrees; it does not stop independent read-only inspection or alter their source checkouts. A pending/uncertain file/Git operation also blocks workspace deletion, source copy/import and explicit release until its exact helper is confirmed retired. Conversation recovery must not release another operation's reservation; use typed ownership/epoch CAS rather than treating every writer as a conversation.

### Resolve an uncertain file/Git reservation

An uncertain operation exposes **Inspect and fence this file/Git operation**, followed only after a confirmed result by **Acknowledge unknown effects and release workspace**. These actions do not use the conversation-recovery endpoint. `POST /file-operations/{operationId}/inspect` requires `{expectedEpoch}` and a timestamped Idempotency-Key; an explicit retry includes `{inspectionId, expectedAttempt, expectedEpoch}`. Only that operation's unresolved typed reservation is eligible. A durable inspection record retains at most three deliberate attempts, each with its own reserved intent alias; exact-key reconciliation precedes changed-state admission. Concurrent distinct attempts conflict, and exhaustion remains visibly blocked for administrator recovery rather than enabling unlimited retries.

Under current authority → project/common → workspace → operation lock order, the supervisor rechecks the exact operation/epoch, confirms immutable owned helper retirement and advances its fence before bounded read-only inspection of the recorded file/index/ref/object and trusted receipt. It never launches the original mutation or infers completion from matching bytes alone. Return a bounded report distinguishing an authenticated completed receipt, observed old/new/conflicting state, missing evidence and unknown durability. Any unconfirmed retirement or failed ownership CAS keeps the typed reservation and marks inspection failed. Database loss retains settlement repair; restart cannot silently turn a pending inspection into release.

`POST /file-operations/{operationId}/release` requires `{inspectionId, expectedEpoch, acknowledgeUnknownEffects:true}` and a new key. The caller reviews the report and retained file/index/ref state first. In one ownership-locked transaction require the successful current inspection/fence and exact typed operation owner, acknowledge the unresolved outcome without relabeling it successful, then CAS-release that reservation and consume the inspection. Original uncertainty, trusted result/receipt and provenance remain readable. No file overwrite, patch, ref update or old command replay occurs; a later edit/Git action needs fresh current revisions and an entirely new operation. A stale/two-tab request returns 409; the exact accepted key still returns its original release result after response loss/restart.

Both browser and authenticated API clients can use this bounded flow with the original operation's project grant plus `files:write` or `git:write` and workspace-write ceiling; current owner-browser authority can recover a revoked creator's abandoned operation. The inspection accepts no arbitrary target or helper ID. Reserve three inspection aliases and one release alias, one inspection record, and at most four audits of 512 bytes with every admitted file/Git mutation; unrelated metadata or ordinary command quota cannot consume that allowance. Reports are at most 16 KiB and use existing bounded native/project content inspection, never a repository copy. Unresolved records are never GC'd to make room. Workspace deletion/release and conversation recovery must recognize this reservation type and reject it rather than clearing its owner. D006 maintenance may invoke its fixed administrator equivalent only with the same exact retirement and recorded acknowledgement rules; backup itself never performs the acknowledgement.

### Bounded persistence and restore

Migration 010 records file/Git operations, typed workspace reservation ownership, safe result/revision metadata and invalidation cursors. Bound retained file/Git operation receipts to 128 per workspace and 4,096 per instance, with at most four queued commands per workspace and four executing helpers per instance. Refuse new mutations before allocating payload/staging at quota. Existing-key reconciliation and exact-owned cleanup remain available at capacity; expired-key rejection follows the token policy’s retention window. Do not evict unresolved receipts or expand capacity through new retry aliases. Payload bytes for file/Git operations in a terminal state are erased after confirmed receipt/result retention; unresolved payloads count toward a 16 MiB per-workspace/64 MiB per-instance control staging quota. Logical limits supplement D003's kernel quota and separate control headroom.

The file module registry includes operation/receipt metadata and only owned pending payload/staging; files, index/objects/refs remain in the complete managed project quota unit. D006 checkpoints must settle accepted effects or fail backup explicitly. Fresh-host restore preserves uncertain history while revoking old effect/retry authority; it must not execute source-host receipts. An older binary that cannot honor the new writer type cannot run against the upgraded active database; rollout/rollback uses the recorded compatibility and backup rules.

### Monaco and corrected effect admission

The authenticated application document carries a fresh `harbor-style-nonce` meta value. Its CSP permits that nonce for styles and retains the existing `script-src 'self'` policy. Monaco 0.56.0 has no public style nonce option: a narrow build adapter stamps only its two pinned, trusted `createElement('style')` factories. The adapter rejects an unexpected factory shape; no global DOM monkey patch or project-controlled HTML receives a nonce. Actual browser CSP/style/worker checks are required when changing this boundary. Terminal assets share the same document nonce seam.

File-operation reload reconciliation also exposes bounded `GET /workspaces/:id/files/operations` and `/git/operations` lists (at most 128 each, their corresponding read scopes). The UI recovers a retained unresolved operation after reload and permits reviewing recent outcomes without relying on a browser-stored intent or secret.

Native filesystem admission: writes use the supported Linux boundary. The macOS private fixture may inspect/render files, but it advertises writes unavailable and rejects new write intents before effects. Complete file acceptance runs on native Linux, and production isolation still requires the managed XFS profile.

Monaco's pinned markup renderers also emit style attributes. The build adapter routes only those reviewed, already-escaped renderer fragments through an attribute lexer: layout attributes become inert before parsing, then are applied through CSSOM before insertion. It neither changes text content nor handles arbitrary repository HTML. Strict style-attribute policy remains in force. Hostile text, diff rendering and CSP assertions are required coverage.

Required-object verification is bounded to 10,000 distinct tree/blob/commit objects, depth 32 and 32 MiB decoded object bytes, with an individual object bound of 16 MiB. The fixed helper verifies exact Git object hashes before index/ref publication, then rechecks the same recorded result after publication and before the filesystem barrier. An exceeded budget is an explicit incomplete review, not permission to omit validation. Prepared index/ref identities are fsynced by the trusted broker through a fixed acknowledgement before publication; dropped acknowledgements never cause original-effect replay.

Helper capacity is a private four-entry ledger updated under a process-released OS lock, with atomic fsynced replacement. A broker crash retains its reservation. Only a recorded dead broker older than the bounded 120-second launch/cleanup grace can be reclaimed, after exact labeled container retirement; PID reuse or unconfirmed retirement fails closed. Cleanup compares the operation identity under the same lock, so an old cleanup cannot remove a successor's reservation. The ledger and its lock are included in the module's control-state inventory.

Uncertainty blocks admission as well as dispatch. When a file effect becomes uncertain, queued successors for its workspace (and related project Git mutations for a Git effect) fail with a visible predecessor-uncertain reason; releasing the reservation never silently starts those old queued intents. A later edit requires a newly accepted operation with current revisions. Conversation/terminal uncertainty likewise cannot be bypassed by requesting a file write. Inspection and acknowledgement remain separately available.

Archived registered workspaces remain available for authorized bounded inspection and downloads; new file/Git mutations require the ready, unarchived state. Removing, failed or unavailable workspaces are not file-access aliases.

## Attachments and drafts

The composer supports file selection, drag/drop, clipboard image paste, upload progress, attachment previews/removal, and submission of text with validated attachment references. Preserve a bounded draft across an ordinary page reload without storing credentials. Display effective model modalities and reject unsupported combinations before dispatch. Basic model, reasoning and permission controls follow the conversation design.

Provide authenticated staging/upload/read/delete operations and allow the turn API to reference staged attachment IDs. An attachment is not sent to Codex until submission accepts its validated references. Partial/cancelled uploads are distinguishable from attached content. Full document conversion/OCR, automatic archive extraction, public sharing, voice, and arbitrary URL imports are excluded.

Store opaque attachment ID, ownership/session binding, staged/attached lifecycle, detected media type, size/hash, safe display name, storage reference, and expiry. Atomically validate attachment availability and associate it with accepted turn intent. A submitted attachment cannot be garbage-collected as an abandoned upload.

Use the [upload and rendering boundary](../architecture.md#execution-and-filesystem-isolation): private bounded storage, generated storage names, type/signature checks, no trusted user MIME/paths, no automatic executable HTML/SVG rendering, and per-upload/count/quota limits. Expose files to the runtime through scoped references or controlled workspace copies only. The browser/API cannot choose a host path or fetch a secret file by impersonating an attachment reference.

Discover and capability-test the pinned runtime's accepted input types. A UI fixture showing an image bubble does not prove the real model received an image. Keep ordinary prompts, attachment metadata, and credentials separate; do not echo sensitive upload bytes into operational logs.

[P024](../proposals/archive/024-attachments-and-chat-composer.md) expands the accepted profile to normalized PNG/JPEG images and general opaque files, preserving strict UTF-8 text compatibility. Images are bounded to 16 million pixels/8192 pixels per side, fully decoded, orientation-normalized and stripped of metadata with pinned Sharp 0.35.4. Other formats are not rendered or extracted. Limits are 10 MiB per upload/normalized file, four references/20 MiB per turn, 32 records/100 MiB per session and 500 MiB per instance. Admission reserves the larger original/normalized byte count. Names are escaped display metadata, never storage paths. The initial candidate missed installed ownership and umask constraints. The [installed correction](../../docs/reports/2026-09-21-p024-installed-attachment-fix.md#final-deployment-and-installed-acceptance) is deployed with hardened Linux publication, actual-model image/file delivery, protected submission and installed composer acceptance. The historical [execution record](../../docs/reports/2026-09-21-p024-attachments-and-composer.md) preserves the original evidence and its limits.

Uploads are private PostgreSQL blobs, alongside opaque session/project identity, declared size/hash, detected media, expiry and lifecycle. Creating an upload record is idempotent; its single bounded binary PUT validates the complete body and atomically commits it as staged. An interrupted PUT publishes no partial bytes and can retry against the same upload ID/hash. Lost committed responses reconcile by reading the record or repeating the identical request. Stage-to-attached association and draft clearing occur in the same transaction as accepted turn intent. GC marks expired unreferenced records under the same session lock and clears only their blobs; referenced content is retained. Bounded tombstones preserve the supported retry window. No upload filesystem publication occurs before commit. An oversized binary body still returns 413 through the reverse proxy. For the pinned parser's body-too-large error only, discard the remaining framed request without buffering for at most five seconds so the rejection can reach the client; destroy that exact unfinished request/socket at the absolute deadline. This changes neither the parser byte limit nor attachment admission. Malformed and aborted framing retains fail-closed handling, and a following request cannot begin before the earlier body boundary.

After dispatch admission, the supervisor resolves only that operation's committed attachment IDs and publishes immutable copies under the managed project quota, at `attachments/<session-id>/<attachment-id>`. A narrow trusted helper checks the root and exact names, creates root-owned directories and read-only files, verifies existing content by digest for replay-safe publication, and fsyncs publication. A committed blob remains authoritative across failed filesystem/DB acknowledgements. Only the selected session directory is mounted read-only at `/attachments`; it is absent from writable sandbox roots. Retrying publication cannot resend a turn. Native input uses the pinned `localImage` form for normalized PNG/JPEG and a text item naming the fixed path for other files. Runtime tools determine format readability; Harbor promises no automatic conversion or universal parsing. Physical copies remain with referenced native conversation history; staged GC never touches them. The supervisor resolves the registered project identity separately from the selected checkout through the session/workspace/project database binding. The quota helper checks that project canonical path and inode under its storage lock; the launcher checks the same project identity and verifies that the selected Local or derived checkout belongs to it before mounting the session attachments. Selected workspace identity must never replace the project identity used to authorize the attachment mount.

Model modalities are taken from pinned runtime discovery; missing image modality fails closed for image dispatch. The browser shows the same capability decision and preserves attached reference identities in history. These are protocol support decisions, not evidence of a real image-aware response. The [official app-server documentation](https://learn.chatgpt.com/docs/app-server) documents `text`, `image` and `localImage` input and model discovery; pinned 0.153.4 generated schemas remain the exact transport contract. The selected personal VPS [live image/file delivery](../../docs/reports/2026-09-21-p024-attachments-and-composer.md#passing-live-delivery) passed. Older managed-profile dedicated live-account evidence remains blocked by the [existing live-test credential issue](../../issues/2026-09-07-171225-live-runtime-credentials.md).

Draft text and selected attachment IDs are stored in a bounded owner/session database draft with revision CAS and a 24-hour expiry, never in browser persistent storage. Credentials belong exclusively in the existing credential setup UI. Submission clears only the exact accepted draft revision; another tab's newer draft is not silently erased. Failed or ambiguous turn submission preserves its exact intent and draft. Upload UI reports progress, permits abort, and requires reselecting an incomplete file after reload before retrying its immutable size/hash identity. Previews render only normalized PNG/JPEG or escaped text; every download has attachment disposition, nosniff, no-store and owner authorization. New attachment/draft routes are browser-owner-only unless an explicit future PAT descriptor grants them.

Personal profiles use a private, service-owned `home/attachments/<session-id>/<attachment-id>` sibling of their configured dedicated Codex home, outside project/development-cache writable roots. A fixed publication helper validates canonical ancestor ownership, uses no-follow directory/file descriptors, immutable read-only generated names and exact content/identity checks. The adapter admits only the server-established session directory, never a caller-chosen path. Copies remain for submitted native history; archive/staging GC cannot delete them. Missing unbound copies can be recreated from authoritative blobs; recorded identity substitutions fail closed. The installed state container may be root-owned 0711 with no group/other write access; local/test containers may instead be service-owned 0700. Traverse trusted ancestors without requiring directory listing, preserving no-follow descriptor checks. Dedicated Codex home and home/attachments children remain service-owned 0700. Set each newly created attachment descriptor explicitly to 0444 before publication and fsync, independent of the service umask 0077. Existing copies must already satisfy exact mode, identity and content checks; never repair unknown substitutions. Personal state checkpoints include the copies. Same-UID personal execution does not promise cross-project read isolation.

The managed backup registry entry is the attachment/draft metadata and blobs in PostgreSQL plus materialized per-session attachment directories within each complete project quota unit. A restore must revalidate directory/file identities before admitting a runtime. No source folder, native history or attachment is deleted by archive. Permanent attached-content deletion is excluded.

## Persistent terminals

Give each terminal its own supervisor-owned Codex stdio connection and immutable runner generation. Do not attach a shell to a conversation runtime: retiring a terminal must not kill an unrelated conversation. The selected registered project/workspace and effective read-only or workspace-write profile are immutable for that terminal. Use the same fixed nonroot image, mount identity, seccomp, resource and XFS quota enforcement as managed workspaces, with an explicit terminal launcher purpose. The managed terminal purpose has no external network, model gateway or model credential. It opens no thread/turn and needs no account authorization. General development egress is unavailable until a separate trusted profile is designed and tested; arbitrary terminal input cannot change that policy.

The terminal purpose selects a fixed seccomp profile derived from D003's unchanged base profile plus only `ioctl(TIOCSPTLCK)` (`0x40045431` on the supported arm64/x86_64 profile), required to unlock a newly allocated PTY. Other write-direction ioctls remain denied, including XFS project/inheritance changes. Keep the derivative checked byte-for-structure against the base plus this exact exception and prove both native PTY creation and quota-escape denials on Linux. [Linux 6.8 PTY request definitions](https://raw.githubusercontent.com/torvalds/linux/v6.8/include/uapi/asm-generic/ioctls.h)

After successful trusted runner admission, terminal commands use the pinned `externalSandbox` policy with `networkAccess:"restricted"`. Codex's nested bubblewrap sandbox is intentionally absent: its namespace creation is denied by the unchanged outer profile. The Docker boundary enforces the immutable UI permission profile through the selected checkout/common mounts (read-only or writable), read-only root, no host/admin mounts, `network:none`, nonroot UID, resource limits and XFS project quota. External mode is selected only by the private factory after successful confined launch, never by a public field or as a host fallback; standalone native smoke tests retain Codex's inner sandbox. Changed terminal boundaries require actual Linux acceptance of both permission profiles, namespace/host/network denials and quota inheritance. Do not grant nested namespace creation to bypass a native sandbox failure. [Official external sandbox contract](https://learn.chatgpt.com/docs/app-server#command-execution)

Use only pinned `command/exec` with `tty:true`, a server-generated connection-scoped process ID, fixed `/bin/bash --noprofile --norc -i`, and server-derived `/workspace`, environment and sandbox policy. Neither HTTP nor WebSocket accepts argv, host paths, environment overrides, permission flags, RPC method names or process IDs. Set an explicit 24-hour lifetime, show its deadline, and keep a supervisor deadline independent of the native timer. Changing or reopening a terminal requires a new explicit identity; a dead generation never restarts a command. Its private empty Codex home belongs to the terminal's project quota unit and contains no conversation credential or native thread state.

The pinned generated types and upstream implementation show that `command/exec` completes only after the process exits, while output and control are separate messages. Add a purpose-specific long-lived adapter operation rather than extending every RPC's 15-second timeout. Persist dispatching before the one launch write. Establish readiness through the exact process's bounded control acknowledgement, not an arbitrary prompt string or the eventual exit response; a fixed-size resize is an idempotent readiness probe. Only an explicit native not-yet-present result may retry that probe within the startup deadline, never the launch or input bytes. A lost launch acknowledgement remains uncertain until the exact runner is retired. Prove readiness, resize, output ordering, exit and termination against the real pinned runtime before declaring the adapter supported. [Pinned protocol implementation](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/app-server/src/command_exec.rs), [official command interface](https://learn.chatgpt.com/docs/app-server#command-execution)

Introduce a typed reservation owner shared with P003/P004: kind, owner ID and monotonically increasing epoch. All existing conversation, workspace storage, recovery and file/Git paths must recognize terminal ownership and preserve it. Lock current actor authority before project/common, workspace and terminal state; recheck current authority after waits and immediately before a new control write. Both terminal profiles conservatively hold the workspace writer reservation. A shell exit alone cannot release it while background descendants or uncertain retirement remain. A terminal's dedicated runner remains visible as **Shell exited; background work may remain** until exact owned runner retirement is confirmed; termination removes the whole terminal runner and confirms absence before ownership CAS release. P003/P007 cannot release a terminal through a conversation recovery endpoint.

Admit at most four live terminal runners per instance, one active terminal per workspace, and two queued terminal creations per workspace. Waiting behind a turn or file/Git operation is visible and does not start a speculative process. Queued starts revalidate their original actor, current project state, permissions, storage and reservation before execution. Normal browser/PAT expiry removes interactive access while an already-authorized shell continues within its fixed lifetime; an emergency stop or administrator drain can explicitly retire it.

### Authenticated HTTP and terminal stream

Expose workspace-scoped terminal listing/creation and terminal-scoped metadata, output, control acquisition, input, resize and termination under `/api/v1`. Creation, control acquisition and termination use the existing durable Idempotency-Key contract. Responses expose Harbor IDs, workspace labels, state, deadline, output watermarks, control ownership and safe failure reasons; host paths, native process handles and launcher identities remain private. OpenAPI declares each route and WebSocket message schema separately. Tokens require explicit `terminal:read`, `terminal:control` and `terminal:terminate` scopes with project grants; existing tokens gain none automatically. Creating or controlling a workspace-write terminal also requires that permission ceiling. Termination requires its own scope and project grant but does not require the target's write ceiling, preserving administrative stop access.

WebSocket upgrades authenticate using the owner cookie or an explicit non-browser Authorization header and validate exact browser Origin. Never put a bearer token or reusable connection credential in a query string or subprotocol. A browser's first bounded protocol message supplies its CSRF token before mutation is enabled. A missing Origin is allowed only for a valid cookie-free API token. The server rechecks authority for every control/input action and closes affected viewers on expiry/revocation; periodic stream checks supplement immediate local revocation events. If authority storage is unavailable, new input and control fail closed.

Only one current controller may send bytes or resize. Other tabs show a read-only viewer and an explicit **Take control** action. A controller lease has a persisted epoch and short expiry renewed by authenticated heartbeat; deliberate takeover compares the expected epoch and fences old frames. Connection loss or lease expiry detaches control without terminating the shell. Reconnection never silently takes control or replays unacknowledged keystrokes. Every message carries protocol version, terminal generation, controller epoch and a sequence appropriate to its action; stale identities fail without touching the current process.

Input is 1–4,096 decoded bytes per frame; reject empty input. Allow at most 128 pending mailbox records, 64 KiB of pending bytes per terminal and 256 KiB of input per minute. Pending records are counted separately from the 128 retained settled outcomes, and both row/byte admission checks run before persistence. Input is limited to 20 frames per second per controller, resize to four per second, and heartbeat to one per five seconds; other controls permit at most four per second with their own durable alias bounds. Bound base64 syntax, queued controls and connection memory independently of JSON body limits; disable WebSocket compression. Coalesce resize to one pending value with dimensions of 20–240 columns and 5–80 rows. Allow at most four viewers per terminal, eight per actor and sixteen per instance, with bounded heartbeat/idle deadlines and a 256 KiB socket send backlog before detachment. A slow viewer cannot block process output or other viewers.

Accept input through a bounded durable mailbox owned by the supervisor; HTTP and WebSocket use the same function. Persist each controller-epoch/sequence and byte hash before acknowledging acceptance, reject a changed retry, and advance through accepted → dispatching → delivered/denied/uncertain. The separate authenticated POST `/terminals/{id}/input/outcome` validates the original generation, controller epoch, sequence, actor and byte hash, and returns retained, missing or expired outcome information without admitting input or renewing control. Missing and expired results never write bytes. Keep at most 128 recent input outcomes, erase payloads once delivery/denial is settled, and reject admission before exceeding the pending byte budget. A native write acknowledgement means delivery to the process input path, not completion of a shell command. A transport/supervisor loss after dispatch marks bytes uncertain and never resends them. Show that gap before explicit reacquisition with acknowledgement; safe un-dispatched frames still require fresh authority before dispatch. Store sequence high-watermarks so outcome pruning cannot authorize an old sequence anew. Logs and audits contain bounded metadata, never keystrokes or echoed secrets.

### Output retention and browser behavior

Persist output independently of chat as exact byte chunks with monotonically increasing terminal sequence and generation, after bounded native decoding. Retain at most 2 MiB and 24 hours per terminal, enforcing count/byte and age limits during appends and reads; durable terminal/uncertainty metadata has a separate lifetime. Bound each stored chunk to 16 KiB, coalesce small output, and retain an explicit floor/gap watermark. Snapshot and subscription use one sequence contract so a commit between them is replayed exactly once. API restart leaves the supervisor's stdio and PTY alive; loss of the supervisor/runner or host reboot yields interrupted/uncertain state without replay.

Limit output processing to 1 MiB per second per terminal and bounded in-memory queues. Drain and mark discarded intervals explicitly; a sustained overload or inability to preserve required state triggers exact terminal retirement with an output-limit/storage failure reason. Never allow silent upstream truncation: request continuous streaming with Harbor's own enforced retention/throughput bounds and recognize the pinned `capReached` notification. A bounded storage outage may lose replay bytes, but cannot fabricate an uninterrupted transcript or free an unconfirmed reservation. Preserve operational headroom for termination, event-gap metadata and ownership settlement.

Lazy-load authenticated, self-hosted `@xterm/xterm` 6.0.0 and `@xterm/addon-fit` 0.11.0, pinned with the lockfile; use no image, clipboard, web-link or remote-font addons. These versions are verified against their upstream release package manifests. Keep a 2,000-line browser scrollback and a bounded rendering queue. Dispose the terminal, listeners and viewer connection when switching panels, while preserving the supervisor process. Show workspace/profile, process state, current control, detach/terminate actions, elapsed lifetime and replay-gap notice around the terminal, including a usable narrow-screen layout. [xterm release](https://github.com/xtermjs/xterm.js/releases/tag/6.0.0), [fit addon version](https://github.com/xtermjs/xterm.js/blob/6.0.0/addons/addon-fit/package.json)

The pinned renderer creates dynamic style elements. Serve a fresh style-only CSP nonce in each authenticated application document and apply it only to the pinned renderer's three style factories through a bounded build adapter. The adapter also uses the style CSSOM for renderer-owned cell styles instead of assigning a style HTML attribute. Fail the build if the pinned factory shape changes; do not globally patch document methods. Keep script policy unchanged and do not enable `unsafe-inline`; actual browser acceptance must verify resize/render behavior and that hostile output cannot create application markup or external loads.

Treat output as untrusted terminal bytes, never application HTML, title, URL, image or clipboard instructions. Disable OSC clipboard/link integration and automatic external resources. Copy/paste requires an explicit local user action; multiline paste shows the exact content before sending, within the same byte limits. Read-only viewers and replay rendering cannot emit terminal-generated input back to the process. The current live controller's protocol responses, if supported, use the same authorized/rate-limited input path. On a gap reset parser/display state and show that a truncated tail cannot reproduce an arbitrary full-screen application; do not present a partial ANSI tail as a faithful saved screen. [xterm security guidance](https://xtermjs.org/docs/guides/security/)

### Cleanup and restore

Retain at most 64 terminal records per project and 256 per instance. Never evict active, queued, unresolved or reservation-owning records to make room. An explicit metadata cleanup removes only terminal records whose exact runner retirement and reservation settlement are confirmed; expired output is independently eligible. Reserve a bounded termination record with at most three deliberate attempt aliases per admitted terminal, reusing the same target identity after a failed attempt; exact retries work at ordinary capacity. After exhaustion, leave explicit administrator recovery instead of accepting unlimited new aliases. Termination cannot be reported complete while the launcher or database cannot establish absence and settlement.

Extend the managed deployment service’s installed module registry with terminal metadata, retained output and private project-quota directories. Checkpoints must drain or explicitly interrupt terminals and confirm all descendants retired. Restore preserves visible history, expired output/gaps and original uncertainty, invalidates controller/input authority, and marks processes stopped; it must not launch a PTY, contact a source-host runtime or replay pending bytes. Compatible promotion drains terminals or shows the consequence of interrupting them before replacing their supervisor.

Extend the six acceptance cases with actual no-account pinned PTY readiness and delayed exit beyond the ordinary RPC timeout; Local and derived Git workspace mounts; browser close and API-only restart while a real shell emits output; two controllers/takeover/stale frames; duplicate/lost input acknowledgements without duplicate bytes; expiry behind locks and queued control denial; database loss before/after input dispatch; output retention and snapshot race; split UTF-8/ANSI payloads, hostile OSC/HTML/links and replay-generated input suppression; slow readers/floods; shell exit with a surviving background process; all queued/live/retained/input/output limits; and P003/P004/P007 typed-reservation conflicts. The supported Linux lane must exercise the actual launcher, pinned PTY and negative filesystem/network/privilege probes. A native PTY which needs no model key can be verified without claiming a live model turn; any account-dependent operation added later retains its separate live gate.

## Managed private previews

Provide create/start/stop preview, readiness/failure state, private opening in a separate tab, bounded process logs, and cleanup. A preview refers to a registered workspace, fixed execution profile, and an allowed application port inside its runner. The browser shows which workspace/process is being viewed.

The initial feature supports ordinary project HTTP applications and explicitly tested upgrade/stream behavior. It excludes full browser automation, unrestricted remote URL fetching, public sharing, arbitrary host port forwarding, and desktop browser-account synchronization. P010 has its own narrowly scoped candidate inspection path and does not depend on this general preview feature.

[D007 — Separate project-preview origins and a confined runner connection](../decisions/007-confined-project-preview-origins.md) is the accepted implementation boundary after independent design review. It owns unique origins, the body-only browser grant exchange, a fixed loopback relay over the exact no-egress runner namespace, and reader/exclusive-writer lifetime rules. It does not weaken D001, the stable Harbor CSP, or the public workspace-management gate.

Store preview ID, workspace/runtime generation, permitted internal destination, lifecycle, process ownership, access grant, and expiry. Creation is an authenticated durable operation; stopping a preview confirms process/proxy termination and does not cancel an unrelated conversation implicitly.

Serve active project content on a separate origin from Harbor with no Harbor session cookie, broad credentials, or control-plane API authority. Bind preview grants narrowly and expire/revoke them with ownership/session policy. Test the preview authentication bootstrap without placing bearer secrets in URLs. Embedding is excluded from the initial profile; the preview cannot command Harbor through a parent or opener window.

The trusted proxy resolves only registered runner destinations. Block metadata/control/database/private-host destinations, redirects or DNS changes that escape the allowed destination, and arbitrary browser-supplied upstreams. Enforce protocol, size, connection, lifetime, and egress limits. Preview processes retain appropriate workspace/resource reservations. Treat all preview JavaScript as project code, not trusted UI.

- Initial create/start selects a registered workspace, a package script matching a bounded identifier grammar, `read-only` or `workspace-write`, and a server-allowed port between 1024 and 65535. The trusted profile runs the pinned npm executable with `run <script>` and fixed working directory/environment, including the stored `PORT`; it accepts no user argv, shell command, executable path, environment map, upstream URL, DNS name, Dockerfile or launch flags. Package scripts remain arbitrary project code inside the confined runner. Dependencies must already exist, and applications must respect the configured loopback port. The UI states this supported profile and reports missing scripts/dependencies/read-only writes without installing or broadening permissions automatically.
- Use a dedicated non-account `command/exec` transport, a fresh private native home under the project's quota unit, stable server-generated process ID and a 24-hour lifetime. Separate the long-running response from the adapter's ordinary request deadline and use only demonstrated native readiness/control acknowledgements; an HTTP readiness success alone does not prove ownership of the process that answered. Persist process/runner/relay generations and lease identities before native send. Readiness requires the exact live execution plus a bounded successful request to its fixed relay destination. A premature exit, lost acknowledgement, mismatched generation or excessive startup interval is visible failed/uncertain state, never an automatic relaunch.
- Expose authenticated `/api/v1/previews`, `/previews/{id}`, `/previews/{id}/start`, `/previews/{id}/stop`, `/previews/{id}/open`, and `/previews/{id}/logs`; all abbreviated routes remain under `/api/v1`. Create/start/stop/open use ordinary actor/route idempotency, current project authority, expected revision/generation where applicable and exact browser Origin/CSRF. New PAT scopes are `previews:read` for metadata/logs, `previews:manage` plus `execute` and the selected ceiling for create/start, and `previews:manage` plus `cancel` for stop. Stop does not require the stopped process's write ceiling. Open/browser grants are owner-browser-only. Existing tokens gain no new scope automatically and unknown routes remain denied.
- A source browser/PAT grant is checked after all admission waits and immediately before first execution. Session/token expiry or revocation removes that actor's future management authority but does not undo already accepted process effects; the bounded process may finish or be explicitly stopped. Viewer grants are separately bound to their current owner browser session, whose expiry/revocation closes those viewers; a source execution PAT cannot mint or replace that viewer authority. New opening intents require current browser authority. Emergency stop closes every preview grant and retires its owned processes. A state change, restart or stop invalidates old relay routes/grants before a new generation can become ready. API restart reconnects only to a demonstrably same supervised process; supervisor/host restart marks launches interrupted/uncertain and requires deliberate start after exact retirement, never replays the old script.
- Allow at most four active previews per instance, one per workspace, and one queued start per workspace. Retain at most 32 preview records per project/128 per instance with no deletion of unresolved owners. Default access lasts at most 15 minutes and never beyond the source browser session; opening again is an explicit renewed access grant, with at most four viewer grants per preview and eight per actor. Opening tickets last 30 seconds, are single-use, and have at most eight pending intents per actor/32 per instance. Expired ticket hashes are retained only for the finite retry window; old unknown timestamped intents cannot become new grants.
- Bound script identifiers to 64 ASCII bytes, names to 160 UTF-8 bytes and metadata/error fields to 4 KiB. Persist process output as escaped text with sequence/generation, at most 1 MiB per preview/24 hours and 16 KiB per chunk, plus a visible truncation watermark. Enforce a 64 KiB/s sustained log rate and bounded in-memory buffering; retire persistent output floods. Keep at most 128 ordinary command-result aliases per preview with three reserved stop attempts and one exact failed-retirement acknowledgement reference. Retrying a stop reconciles that attempt and never consumes another alias indefinitely.

Limit request bodies to 8 MiB, headers to 16 KiB/100 fields, paths/queries to 8 KiB, responses to 32 MiB and ordinary requests to 30 seconds. Reject malformed or oversized upstream responses before treating their bytes as another frame. Do not follow redirects; accept only a validated same-origin Location that cannot reach the reserved bootstrap namespace.
- Support SSE and WebSocket upgrades only through explicit tested paths, fresh authority and the same fixed upstream. Disable compression and arbitrary protocols; bound WebSocket messages to 64 KiB, send backlog to 256 KiB, stream throughput to 2 MiB/minute, stream lifetime to 15 minutes, and concurrent upstream connections to eight per preview/32 per instance. Refresh authority at most one second apart, enforce D007's independent five-second maximum unrenewed lease, and close on expiry/revocation/revalidation failure even while idle or awaiting a database result. Check the lease before each newly forwarded frame. Test idle SSE/WebSocket connections across source-browser revocation, owner replacement and database unavailability, asserting closure/forwarding bounds as well as fresh-connection denial. Use bounded connection/header deadlines and close backpressure visibly. Reconnection may establish a new authorized transport; it cannot replay application messages or restart a process. - Add responsive workspace preview controls, profile/script/port configuration, readiness/error/log state, explicit Open in new tab, access expiry, stop and confirmed cleanup status.
