## Managed installation and recovery

[D006](../decisions/006-portable-release-and-restore.md) owns the accepted immutable packaging, service privilege, encrypted consistency checkpoint, module registry, destination rebinding and administrator contract. Compatible Linux hosts need tested kernel/container/XFS isolation; provider labels are not capabilities. The managed profile currently uses a trusted root supervisor and separate storage service, unprivileged API and private dependencies. Do not claim stronger separation than the actual launcher provides.

Build immutable versioned artifacts with exact source/dependency/runtime/image and migration identities. Administrator tooling accepts fixed operations over configured instances and owned roots; the browser never supplies host commands, mount flags or arbitrary release paths. Require actual readiness and deny public fixture/native-personal combinations, missing isolation and exposed control ports. Preserve an SSH recovery path independent of Harbor.

Checkpoint freezes admission/configuration, drains settled effects or visibly interrupts with confirmed retirement, then captures PostgreSQL, complete managed project/native quota units, attachments and delivered modules plus protected configuration consistently. Required module entries must match actual delivered schema and inventory. Do not manufacture empty entries for undeployed modules or omit an unknown table. Encrypt off-host backups; keep repository credentials and recovery keys out of project code and ordinary logs. Verify complete stored data and registry integrity before treating a snapshot as recoverable.

Restore into a separate disabled instance on a fresh compatible host. Validate all bytes, links, modules, decryption material and resource limits before publication. Changed filesystem identities require trusted destination validation, never unchecked path rebinding. Re-encrypt credentials for destination ownership; revoke old sessions/PATs/schedule/development/viewer/extension grants and execution receipts as applicable. Preserve original completed/interrupted/uncertain history; old native locks and source launcher identities cannot authorize destination effects. No automatic queued turn, terminal input, file/Git mutation, preview, scheduled occurrence or deferred job is replayed. Do not contact source-host runtimes. Enable admission only after full validation and explicit destination activation. Future backup destination enrollment is separate from restore-source authority and rejects a destination that is not off-host.

Promotion references the exact tested immutable artifact and compatibility report, drains or explicitly interrupts active work, and retains a consistent private checkpoint. Refuse unsupported migration/native/runtime downgrade; compatible rollback retains state consequences and incompatible rollback needs a documented restore/forward-repair path. Backup corruption, missing keys/modules, process loss, disk pressure and failed publication must preserve the healthy installation, fail closed and clean only owned staging. Administrator locks, source identities, fixed SSH host trust and resource manifests govern retry/recovery.

Delivered module restoration has concrete requirements: projects/workspaces/native history retain mappings; attachment blobs and references survive; file operations retain uncertainty but lose old inspection/effect authority; terminal processes stay stopped with controller/input revoked; schedules stay paused with old jobs blocked; previews stay inactive with access grants revoked. Future self-development/extension state is registered only when delivered and must follow its own disabled historical restore contract.

## Personal local profile

[D010](../decisions/010-personal-local-experience.md) authorizes native account execution on a personal computer, separate from managed Linux isolation. `pnpm dev --local` checks prerequisites, creates independent persistent state and private native account home, uses official login and owner authentication, and binds loopback. It must reject production/fixture/nonlocal combinations and keep normal Origin/CSRF/idempotency semantics. Configuration/runtime incompatibility and missing login fail visibly; do not use ordinary personal Codex state implicitly.

Use actual approved local paths through the adapter. Native read-only permission is the delivered local ceiling, and unsupported managed operations fail before execution. Account readiness reflects the current native state. Browser/API disconnect does not replay a turn; runtime loss preserves uncertainty. P018 probes showed that ordinary native commands, not only hostile detached descendants, escape group-only inspection/retirement. Linux therefore requires delegated generation cgroup ownership; native macOS lifecycle support is outside the owner-selected VPS-only release and incomplete inspection fails closed. Explicit uncertain local recovery remains unavailable. Local owner text-conversation evidence is not managed live-account acceptance.

## Personal VPS profile

[D011](../decisions/011-personal-vps-workspace.md) owns the explicit change from the managed container/XFS contract for this personal profile. Include owner OIDC login, protected browser/API/SSE, native account onboarding, administrator-approved existing roots, original Local folder writes, durable conversations, model discovery, stop/reconnect and systemd startup. Native account login is a trusted SSH administrator operation with a stopped supervisor; the owner completes the official provider's device flow. The UI reports readiness and explains how to finish login.

Require the complete pinned native distribution, including code-mode host and package-declared sandbox/shell/PATH resources; copying only the Codex entrypoint is not a valid release. Require Linux/systemd, a dedicated nonroot service user without sudo or Docker authority, pinned Node/Codex/dependencies, PostgreSQL, canonical verified HTTPS and an allowlisted real OIDC issuer/client/subject. A trusted existing reverse proxy may terminate HTTPS and forward to the loopback backend. The current host's Traefik must be preserved. State and immutable application assets live outside editable roots. No folder migration or copying is implicit.

Exclude managed worktree/copy creation, interactive file editor, standalone terminal UI, schedules, managed previews, PATs, extensions and self-development brokers in this profile. [P024](../proposals/024-attachments-and-chat-composer.md) adds authenticated personal attachments using private state outside project/cache write grants, with native delivery verification required. [D012](../decisions/012-personal-vps-development.md) adds the selected personal attached preview and complete conversation-driven development workflow. Codex conversation tools may edit the original project within the configured native permission policy. Unsupported capabilities are denied in the API and accurately represented in the UI. Existing profiles retain their behavior. Full P009 backup/restore/promotion remains separate and unverified; personal-profile evidence does not establish its completion.

1. The owner opens the canonical HTTPS URL and signs in through the configured OIDC provider. Existing issuer/subject checks, PKCE/state/nonce, secure opaque cookies, Origin/CSRF checks and bounded command idempotency apply.
2. After deployment, the owner adds an existing folder within administrator-configured browse roots; configuring a root does not pre-register a project. The owner's later explicit authorization permits `/root` as the ceiling, with read/traverse access at `/root` and owner-authorized read/write access to all current and future projects under `/root/Projects`; other descendants remain subject to Unix permissions. The browser may register a descendant or `/root` itself (`.`), but cannot explore unapproved host locations. Multiple disjoint descendants are supported; `/root` and a descendant cannot both be registered because overlapping projects remain forbidden. Registration preserves the original canonical path and filesystem identity; absent, replaced, overlapping or escaped folders fail explicitly.
3. Account settings show native subscription readiness. The administrator uses the separate private Codex home and official login command, or D011's explicitly owner-requested existing-login import, while the supervisor is stopped. No auth.json, access token or API key enters a prompt, ordinary log or browser storage.
4. The owner creates a conversation, chooses an allowed model and read-only or workspace-write policy, and submits a turn. The supervisor persists intent and streams results. Browser closure or SSH disconnect does not stop a systemd service or cancel accepted work. Approvals may pause progress until answered.
5. Reopening fetches retained messages and reconnects without resubmitting work. Successful native threads can continue. Supervisor/runtime loss preserves uncertainty rather than automatically replaying effects. Unsupported recovery controls remain denied; SSH stop/inspection remains available.

Introduce an explicit personal VPS configuration discriminator, separate from local, fixture and managed installed modes. Native-home and binary paths are explicit. Capabilities identify the profile and its supported surfaces without advertising the local-only login command. Existing project/session/operation tables and migration history remain canonical. D012 adds migration 017 for conversation-title provenance and conservative backfill, and migration 018 for retained-runtime expiry and stop requests. Promotion and rollback must use a compatible database/native/config checkpoint.

The API owns authentication and durable commands; one persistent supervisor owns native runtime generations through the adapter. Codex 0.153.4 owns subscription credentials and native history in private persistent state. Adapter initialization, model discovery and granular sandbox policy must pass actual pinned-runtime contracts. Unsupported native capabilities fail closed.

Official Codex supports subscription sign-in and a headless device flow; availability depends on account settings. See [official authentication guidance](https://learn.chatgpt.com/docs/auth). Missing/expired credentials produce unavailable account status and bounded errors, not an API-key fallback or silent use of normal host Codex state.

Apply D011's personal trust model: only the authenticated owner, a dedicated nonroot Unix account, no sudo/Docker socket, immutable root-owned release, private credentials, explicit project roots, native workspace-write sandbox and denied unsandboxed escalation, with D012's explicit development grants. Native read access is broader than the selected workspace; this profile is not suitable for mutually untrusted projects. Same-UID services/native state do not provide the managed profile's control-plane secrecy boundary. Protect other service data with Unix ownership and systemd restrictions, sanitize child environments, and make this limitation visible in operational docs.

The final owner-authorized access plan grants the service account `r-x` on `/root` and `rwX` on existing `/root/Projects` content with directory default ACLs for future descendants. Preserve `/root/.ssh`, unrelated root startup/account files and ownership. Broad root-home writes are superseded to retain SSH StrictModes compatibility and avoid changing root-session startup behavior. Browser selection never grants Unix access; other root-home folders require administrator write grants, and registering `/root` itself does not enable top-level writes. A nonroot UID does not protect files explicitly shared with it. Keep the immutable release, administrator configuration/candidate bundles and all private instance/native state outside `/root`. `/` and other broad system directories remain denied.

Use systemd memory/PID/CPU bounds, a read-only service filesystem except approved project/state paths, and private temporary space. These do not establish XFS hard quotas or confined model egress. Account/provider traffic requires verified TLS. Deny fixture/local mode combinations, root execution, arbitrary roots, state/root overlap, raw runtime access and unsupported feature requests. Existing HTTP/input/history limits remain effective. Test actual native write denials and service restrictions on Linux; do not infer them from configuration text.

### Personal concurrency and upgrade compatibility

[D014](../decisions/014-personal-conversation-concurrency.md) adds shared conversation membership to both personal profiles without changing their permission ceilings. P018/P024 release acceptance targets personal VPS under the owner’s 21 September decision; native macOS lifecycle completion is not planned for this release and is not inferred from Linux results. Administrator limits default to four active turns and four retained/live runtimes, propagate through local startup and VPS rendering, and reject invalid combinations. Migration 019 preserves exact generation ownership and safe runtime lifecycle; deployment must drain old exclusive conversation reservations before migration. Keep matched database/native/config backups. Older binaries must not open the upgraded state. Unknown retirement remains counted and visible; background services do not expire merely because 30 minutes elapsed. Other managed release/restore obligations remain unchanged.

### Conversation-driven development and attached previews

[D012](../decisions/012-personal-vps-development.md) owns explicit development grants: ordinary existing project `.git` metadata, pinned package cache, private temporary space and network access under the native workspace policy. New repositories and linked/external Git metadata are unsupported. Read-only and outside-project write denial still apply; no host administration or unsandboxed escalation is granted. Complete native package layout includes the code-mode host and declared shell/sandbox/PATH helpers. The service remains nonroot, and immutable release/configuration/private native state remain outside editable roots.

The conversation may run Git/read/edit, locked dependency install, tests/build and a loopback development server. Attach only the configured allowed personal development port through the separate HTTPS preview origin. Opening tickets are body-exchanged, short-lived and one-use; viewer grants are current-session bound, expiring and revoked on logout. Strip stable credentials and unsafe forwarding headers, deny arbitrary targets/control-port collisions, bound HTTP/WebSocket behavior and show an unavailable-server state. The personal shared-port/process lifecycle limitation is visible; this is not the managed per-preview runner boundary.

Persist the first substantive task title with provenance; manual rename wins and conservative backfill only replaces default titles. Sidebar/header/reload agree. Streamed and authoritative final text reconcile by actual parent/child turn identity without tool output contamination, duplication or dropped final text. Retained runtime expiry/stop requests are durable; stopping background resources is distinct from cancelling the active answer. Migrations 017/018 require matched database/native/config recovery state for rollback.

Trusted native login or explicitly owner-requested credential-only import requires stopped supervisor work and independent private native state. Trusted owner enrollment obtains the exact verified issuer/subject through bounded state/nonce/PKCE and create-only output; knowing an email alone is not ongoing authorization. No credentials enter prompts, browser storage or retained diagnostics. Fixed renderer/installer commands validate administrator inputs and avoid modifying unrelated reverse proxy, service or source state.
