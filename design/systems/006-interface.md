## Navigation and supporting controls

Keep conversation work primary with grouped projects/chats and contextual supporting tools. Each expanded project initially shows five nonarchived conversations ordered by their latest accepted query time, falling back to conversation creation time, with ID descending as the tie-breaker; Show more requests the next five with the exact history cursor. Selection only highlights the row and leaves identity, cursor, loaded depth and display order unchanged, including when an older conversation opens through a direct link or search. An accepted input refreshes the retained depth and moves that conversation to its durable position. Unsent drafts, metadata edits, assistant/tool output, completion and resource/status changes do not reorder history; search keeps creation order. Refresh preserves loaded depth and selection, deduplicates IDs and rejects stale responses. Sidebar history shows no loading row, spinner or placeholder on initial load, refresh or pagination; existing rows stay in place while requests are pending. The history region remains accessibility-busy and loading disables pagination. Empty, error, retry and Show more text align with conversation title text, separately from search-dialog results; failure retains rows and offers retry. Collapse/reopen may reset depth. The top-sidebar magnifier opens a centered search dialog with initial input focus, explicit current-project scope, active/archived/all filters, archived-project visibility and paged results. Results stay separate from the active sidebar; selecting one closes the dialog and opens it. Escape and backdrop dismiss with focus restoration. Project details expose supported workspace/files/terminal/schedule/preview access; settings open through the bottom-right gear, not toast actions. Unavailable profile features have no functional-looking placeholders. Actionable errors, approval/input and uncertainty remain visible; connection/storage/retention details belong in their contextual dialog.

Project controls follow label, New chat, ellipsis order; the Projects heading Add project button and project/conversation ellipsis centers share the trailing column. Settings retain the Codex account action and unauthenticated Set up cue; authenticated readiness and account details live in the account dialog, with no work-continues sentence in the menu. Conversation/project ellipses use visible round dots and discoverable neutral contrast. Menus and settings have a fixed leading icon column and left-aligned labels. Conversation menus support hover, keyboard focus and touch, preserve revision/idempotency behavior, and rename the targeted inactive or active chat without switching selection or clearing drafts. Archive is visibility-only and never deletes source/history or interrupts active work; the personal profile may retire idle retained resources. Stop background processes retires retained execution/reservation and is distinct from active-answer cancellation. The guide's sole semantic green dot means confirmed retained resources/reservation, never connection health or generation progress. Unknown state cannot be called confirmed idle.

Personal conversations sharing a workspace may each have a confirmed green resource dot. D014 runtime states distinguish ordinary idle, background-service protected, retiring and unknown; active and approval/input work remain visible. Queue explanations identify session serialization, active/runtime capacity, protected resources, uncertain retirement, workspace conflict or maintenance. Keep resource changes independent from the last-accepted-query ordering above. Shared-directory information and targeted stop live in existing context/status surfaces; unknown is never represented as confirmed idle or a green confirmation.

The composer starts at one line, grows to the guide's cap, then scrolls; Enter sends, Shift+Enter adds a line and IME composition never submits. Preserve attachments/settings/steer/cancel and approval/queued/failed/uncertain state. Sidebar resize obeys the guide's desktop bounds and main-content reserve with pointer and keyboard separator controls. Mobile uses a dismissible overlay with inert regions and restored focus; breakpoint changes cannot strand focus. All secondary controls use existing visual roles, keyboard labels and touch access.

## Folder selection

The bounded owner-only `GET /api/v1/project-roots/:id/directories?path=<relative>` is available only in admitted local/private-fixture/personal profiles. It returns relative directory names/paths and explicit truncation, never file content or arbitrary host paths. Configured roots bound descriptor-relative no-follow traversal; reject unknown roots, traversal, inaccessible paths and symlinks. Deny bearer/anonymous access. Registration revalidates identity and overlap; listing grants no filesystem authority. Managed installations retain their relative-path registration form without granting the API host filesystem access. Show loading/empty/truncated/error/retry states. This selects server folders, not browser uploads.

## Content and reasoning controls

Assistant messages use CommonMark/GFM and preserve source through streaming/reload; raw HTML never executes, remote images are explicit links, unsafe schemes are rejected and Mermaid remains labelled source. User input/tool diagnostics stay literal. Wide code/tables scroll internally and remain keyboard focusable. Use the guide's typography and component styles.

The user toolbar deliberately includes decorative, aria-hidden, nonfocusable thumbs-up/down slots after Copy, matching assistant icon size and gap. These slots have no handlers, vote state, requests or persistence; this owner-requested visual exception does not expose feedback controls. User copy uses raw message text and sits beneath, outside its bubble. On hover-capable pointers it appears on message hover or keyboard focus; touch always exposes it and copy failures remain visible. Completed assistant turns have one copy/like/dislike toolbar after their last body segment; full-turn copy joins source body fragments without tools/UI labels. Code/source blocks have a neutral header with language (Text when absent) at top left and copy at top right, outside the scroll area. Locally bundled highlight.js 11.11.1 uses explicit common-language grammars and aliases with no automatic detection or remote loading. At most 32 KiB is highlighted per block, memoized by source/language; unknown, unlabelled, Mermaid and larger blocks remain escaped literal text. Only trusted grammar output supplies markup. Syntax color is a content-only exception to equal-channel neutral shell colors. Preserve code whitespace without fences/language labels and raw Markdown syntax. No per-paragraph buttons. Report success only after clipboard completion and show explicit failure. Assistant reactions are mutually exclusive, toggleable, refresh-reset local state with no request, analytics, counts or stored feedback.

Consecutive tool messages in the same operation render as one compact activity disclosure, closed initially even during streaming. The summary reports command count and running state; expansion survives updates and reveals literal per-command diagnostics without repeated collapsed message headings/timestamps. Approvals, input requests and actionable failure/uncertainty controls remain visible outside the disclosure.

Runtime discovery owns model-specific effort options and the server revalidates them at dispatch. Preserve distinct `low`, `medium`, `high`, `xhigh`, `max` values when supported; labels are Low, Medium, High, Extra High, Max. Never submit `light`, fabricate a missing mode or narrow another model to Astra's options. The historical P016 runtime discovery evidence establishes that tested pin/account, not a permanent guarantee about future model capabilities.

## P024 composer and scrolling

[P024](../proposals/024-attachments-and-chat-composer.md) places transcript, notices and composer in one vertical scroll container below the fixed header, reaching the pane bottom. A normal-flow sticky composer and measured scroll padding preserve short-chat alignment and focused controls. Keep the compact textarea, Enter/Shift+Enter/IME, mobile sidebar and horizontal code/table behavior. Streaming follows only readers already near the bottom; explicit send/selection preserves established behavior. The plus picker, drop and clipboard File items support bounded batches, with no silently discarded extras and ordinary text paste intact. Attachment rows use a real bounded list wrapper; errors/progress remain visible. Use concise labels Archive, Unarchive, Status, Stop processes, Cancel turn, Cancel and Retry upload; preserve descriptive accessible names and Retry same request semantics. The canonical guide/prototype must demonstrate these states before application use. Sidebar ordering remains the existing last-accepted-query contract.

Submission reserves the composer synchronously before awaiting draft persistence. While this reservation is held, text and attachment selection cannot change and repeated Send/Enter cannot create another intent. Queued, hashing, uploading, refreshing and retry-held files synchronously block send admission. Preserve exact uncertain requests for Retry same request; accepted references leave the submitted composer even if subsequent refresh fails, with an explicit recovery state. Reload uses draft revision CAS and must preserve newer drafts from other tabs. The installed P024 correction verifies these transitions under controlled response delays.
