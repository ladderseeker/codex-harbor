## Scope and user/API flow

Add terminal creation, input, resize, output, reconnect, exit status, and explicit termination. The UI shows workspace identity, whether a process is still alive, and whether older output has expired. Closing the panel or browser detaches; it does not terminate the shell. Expose the same create/control lifecycle through authenticated HTTP and terminal WebSocket operations.

Prefer the tested sandboxed PTY capability behind the Codex adapter, as described in the architecture. The feature excludes a host-root terminal, SSH credential manager, terminal persistence through a process death/reboot, and arbitrary process/RPC forwarding. A runtime generation change invalidates old terminal handles.

## Contracts and security

Persist terminal identity, project/workspace, owning runtime generation, process handle, status, granted profile, writer reservation, output sequence, and retention window. Keep binary/encoded terminal output separate from chat markup. Reconnect uses the last sequence or a bounded snapshot with an explicit gap indication.

Treat interactive shell access as arbitrary code execution within its runner. Apply the outer execution boundary even if an upstream operation skips Codex's inner sandbox. Authenticate the upgrade, validate browser Origin, authorize each input/control message, bound bytes/rate/connection count, and close access on credential expiry/revocation. Deliberate user actions are required for links and clipboard integration.

A terminal and its background jobs retain their workspace writer reservation. Managed conflicting writers queue; terminate or move work to another workspace to remove the conflict. Coordination cannot prevent an arbitrary process or external SSH client from editing files. The UI must not imply that keeping a shell open grants safe concurrent edits in the same checkout.

## Independent acceptance

Use P003 with an isolated shell fixture, known workspace markers, delayed output, and a background job. Tests invoke real processes for shell/isolation claims, even though deterministic transport scenarios can use the external protocol fixture.

1. **P006-01:** Create a terminal, run a bounded command, resize it, and inspect its exit/output. Assert the actual workspace and process behavior.
2. **P006-02:** Close every browser while a process emits delayed output, reconnect, and restart only the API. Assert the same process continues and output sequences are not duplicated.
3. **P006-03:** Exceed replay retention and reconnect. Assert a visible output gap rather than fabricated full history; enforce slow-reader and output-size bounds.
4. **P006-04:** End the shell with a background job remaining, terminate it deliberately, and attempt a conflicting managed turn. Assert reservation lifetime and confirmed process cleanup.
5. **P006-05:** Attempt unauthorized/wrong-project control, cross-origin upgrades, stale handles, hostile links/control output, and quota overflow. Revoke access midstream and assert immediate control loss.
6. **P006-06:** With the real pinned PTY implementation on supported Linux, probe forbidden mounts/network/host privileges and kill the runtime. Assert confinement and an honest exited/interrupted terminal state, not automatic command replay.

## Recorded implementation contract — 7 September 2026

These refinements prepare the authorized terminal outcome. Implementation has started in an isolated worktree; source inspection and design review do not establish a working PTY or confinement. Preserve P006-01–06 above.

### Dedicated terminal runtime and writer ownership

Give each terminal its own supervisor-owned Codex stdio connection and immutable runner generation. Do not attach a shell to a conversation runtime: retiring a terminal must not kill an unrelated conversation. The selected registered project/workspace and effective read-only or workspace-write profile are immutable for that terminal. Use the same fixed nonroot image, mount identity, seccomp, resource and XFS quota enforcement as P003, with an explicit terminal launcher purpose. The initial terminal purpose has no external network, model gateway or model credential. It opens no thread/turn and needs no account authorization. General development egress is unavailable until a separate trusted profile is designed and tested; arbitrary terminal input cannot change that policy.

The terminal purpose selects a fixed seccomp profile derived from D003's unchanged base profile plus only `ioctl(TIOCSPTLCK)` (`0x40045431` on the supported arm64/x86_64 profile), required to unlock a newly allocated PTY. Other write-direction ioctls remain denied, including XFS project/inheritance changes. Keep the derivative checked byte-for-structure against the base plus this exact exception and prove both native PTY creation and quota-escape denials on Linux. The first supported Linux checkpoint rejected `openpty` with `EPERM`; no shell or writer release was claimed from that failure. [Linux 6.8 PTY request definitions](https://raw.githubusercontent.com/torvalds/linux/v6.8/include/uapi/asm-generic/ioctls.h)

After successful trusted runner admission, terminal commands use the pinned `externalSandbox` policy with `networkAccess:"restricted"`. Codex's nested bubblewrap sandbox is intentionally absent: its namespace creation is denied by the unchanged outer profile. The Docker boundary enforces the immutable UI permission profile through the selected checkout/common mounts (read-only or writable), read-only root, no host/admin mounts, `network:none`, nonroot UID, resource limits and XFS project quota. External mode is selected only by the private factory after successful confined launch, never by a public field or as a host fallback; standalone native smoke tests retain Codex's inner sandbox. Actual Linux acceptance must establish both permission profiles, namespace/host/network denials and quota inheritance before this mode is supported. The intermediate PTY checkpoint preserved native `bwrap: No permissions to create a new namespace` output; granting namespace creation is not a remedy. [Official external sandbox contract](https://learn.chatgpt.com/docs/app-server#command-execution)

Use only pinned `command/exec` with `tty:true`, a server-generated connection-scoped process ID, fixed `/bin/bash --noprofile --norc -i`, and server-derived `/workspace`, environment and sandbox policy. Neither HTTP nor WebSocket accepts argv, host paths, environment overrides, permission flags, RPC method names or process IDs. Set an explicit 24-hour lifetime, show its deadline, and keep a supervisor deadline independent of the native timer. Changing or reopening a terminal requires a new explicit identity; a dead generation never restarts a command. Its private empty Codex home belongs to the terminal's project quota unit and contains no conversation credential or native thread state.

The pinned generated types and upstream implementation show that `command/exec` completes only after the process exits, while output and control are separate messages. Add a purpose-specific long-lived adapter operation rather than extending every RPC's 15-second timeout. Persist dispatching before the one launch write. Establish readiness through the exact process's bounded control acknowledgement, not an arbitrary prompt string or the eventual exit response; a fixed-size resize is an idempotent readiness probe. Only an explicit native not-yet-present result may retry that probe within the startup deadline, never the launch or input bytes. A lost launch acknowledgement remains uncertain until the exact runner is retired. Prove readiness, resize, output ordering, exit and termination against the real pinned runtime before declaring the adapter supported. [Pinned protocol implementation](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/app-server/src/command_exec.rs), [official command interface](https://learn.chatgpt.com/docs/app-server#command-execution)

Introduce a typed reservation owner shared with P003/P004: kind, owner ID and monotonically increasing epoch. All existing conversation, workspace storage, recovery and file/Git paths must recognize terminal ownership and preserve it. Lock current actor authority before project/common, workspace and terminal state; recheck current authority after waits and immediately before a new control write. Both terminal profiles conservatively hold the workspace writer reservation. A shell exit alone cannot release it while background descendants or uncertain retirement remain. A terminal's dedicated runner remains visible as **Shell exited; background work may remain** until exact owned runner retirement is confirmed; termination removes the whole terminal runner and confirms absence before ownership CAS release. P003/P007 cannot release a terminal through a conversation recovery endpoint.

Admit at most four live terminal runners per instance, one active terminal per workspace, and two queued terminal creations per workspace. Waiting behind a turn or file/Git operation is visible and does not start a speculative process. Queued starts revalidate their original actor, current project state, permissions, storage and reservation before execution. Normal browser/PAT expiry removes interactive access while an already-authorized shell continues within its fixed lifetime; an emergency stop or administrator drain can explicitly retire it.

### Authenticated HTTP and terminal stream

Expose workspace-scoped terminal listing/creation and terminal-scoped metadata, output, control acquisition, input, resize and termination under `/api/v1`. Creation, control acquisition and termination use the existing durable Idempotency-Key contract. Responses expose Harbor IDs, workspace labels, state, deadline, output watermarks, control ownership and safe failure reasons; host paths, native process handles and launcher identities remain private. OpenAPI declares each route and WebSocket message schema separately. P002 adds explicit `terminal:read`, `terminal:control` and `terminal:terminate` scopes with project grants; existing tokens gain none automatically. Creating or controlling a workspace-write terminal also requires that permission ceiling. Termination requires its own scope and project grant but does not require the target's write ceiling, preserving administrative stop access.

WebSocket upgrades authenticate using the owner cookie or an explicit non-browser Authorization header and validate exact browser Origin. Never put a bearer token or reusable connection credential in a query string or subprotocol. A browser's first bounded protocol message supplies its CSRF token before mutation is enabled. A missing Origin is allowed only for a valid cookie-free API token. The server rechecks authority for every control/input action and closes affected viewers on expiry/revocation; periodic stream checks supplement immediate local revocation events. If authority storage is unavailable, new input and control fail closed.

Only one current controller may send bytes or resize. Other tabs show a read-only viewer and an explicit **Take control** action. A controller lease has a persisted epoch and short expiry renewed by authenticated heartbeat; deliberate takeover compares the expected epoch and fences old frames. Connection loss or lease expiry detaches control without terminating the shell. Reconnection never silently takes control or replays unacknowledged keystrokes. Every message carries protocol version, terminal generation, controller epoch and a sequence appropriate to its action; stale identities fail without touching the current process.

Input is 1–4,096 decoded bytes per frame; reject empty input. Allow at most 128 pending mailbox records, 64 KiB of pending bytes per terminal and 256 KiB of input per minute. Pending records are counted separately from the 128 retained settled outcomes, and both row/byte admission checks run before persistence. Input is limited to 20 frames per second per controller, resize to four per second, and heartbeat to one per five seconds; other controls permit at most four per second with their own durable alias bounds. Bound base64 syntax, queued controls and connection memory independently of JSON body limits; disable WebSocket compression. Coalesce resize to one pending value with dimensions of 20–240 columns and 5–80 rows. Allow at most four viewers per terminal, eight per actor and sixteen per instance, with bounded heartbeat/idle deadlines and a 256 KiB socket send backlog before detachment. A slow viewer cannot block process output or other viewers.

Accept input through a bounded durable mailbox owned by the supervisor; HTTP and WebSocket use the same function. Persist each controller-epoch/sequence and byte hash before acknowledging acceptance, reject a changed retry, and advance through accepted → dispatching → delivered/denied/uncertain. The separate authenticated POST `/terminals/{id}/input/outcome` validates the original generation, controller epoch, sequence, actor and byte hash, and returns retained, missing or expired outcome information without admitting input or renewing control. Missing and expired results never write bytes. Keep at most 128 recent input outcomes, erase payloads once delivery/denial is settled, and reject admission before exceeding the pending byte budget. A native write acknowledgement means delivery to the process input path, not completion of a shell command. A transport/supervisor loss after dispatch marks bytes uncertain and never resends them. Show that gap before explicit reacquisition with acknowledgement; safe un-dispatched frames still require fresh authority before dispatch. Store sequence high-watermarks so outcome pruning cannot authorize an old sequence anew. Logs and audits contain bounded metadata, never keystrokes or echoed secrets.

### Output retention and browser behavior

Persist output independently of chat as exact byte chunks with monotonically increasing terminal sequence and generation, after bounded native decoding. Retain at most 2 MiB and 24 hours per terminal, enforcing count/byte and age limits during appends and reads; durable terminal/uncertainty metadata has a separate lifetime. Bound each stored chunk to 16 KiB, coalesce small output, and retain an explicit floor/gap watermark. Snapshot and subscription use one sequence contract so a commit between them is replayed exactly once. API restart leaves the supervisor's stdio and PTY alive; loss of the supervisor/runner or host reboot yields interrupted/uncertain state without replay.

Limit output processing to 1 MiB per second per terminal and bounded in-memory queues. Drain and mark discarded intervals explicitly; a sustained overload or inability to preserve required state triggers exact terminal retirement with an output-limit/storage failure reason. Never allow silent upstream truncation: request continuous streaming with Harbor's own enforced retention/throughput bounds and recognize the pinned `capReached` notification. A bounded storage outage may lose replay bytes, but cannot fabricate an uninterrupted transcript or free an unconfirmed reservation. Preserve operational headroom for termination, event-gap metadata and ownership settlement.

Lazy-load authenticated, self-hosted `@xterm/xterm` 6.0.0 and `@xterm/addon-fit` 0.11.0, pinned with the lockfile; use no image, clipboard, web-link or remote-font addons. These versions are verified against their upstream release package manifests. Keep a 2,000-line browser scrollback and a bounded rendering queue. Dispose the terminal, listeners and viewer connection when switching panels, while preserving the supervisor process. Show workspace/profile, process state, current control, detach/terminate actions, elapsed lifetime and replay-gap notice around the terminal, including a usable narrow-screen layout. [xterm release](https://github.com/xtermjs/xterm.js/releases/tag/6.0.0), [fit addon version](https://github.com/xtermjs/xterm.js/blob/6.0.0/addons/addon-fit/package.json)

The pinned renderer creates dynamic style elements. Serve a fresh style-only CSP nonce in each authenticated application document and apply it only to the pinned renderer's three style factories through a bounded build adapter. The adapter also uses the style CSSOM for renderer-owned cell styles instead of assigning a style HTML attribute. Fail the build if the pinned factory shape changes; do not globally patch document methods. Keep script policy unchanged and do not enable `unsafe-inline`; actual browser acceptance must verify resize/render behavior and that hostile output cannot create application markup or external loads.

Treat output as untrusted terminal bytes, never application HTML, title, URL, image or clipboard instructions. Disable OSC clipboard/link integration and automatic external resources. Copy/paste requires an explicit local user action; multiline paste shows the exact content before sending, within the same byte limits. Read-only viewers and replay rendering cannot emit terminal-generated input back to the process. The current live controller's protocol responses, if supported, use the same authorized/rate-limited input path. On a gap reset parser/display state and show that a truncated tail cannot reproduce an arbitrary full-screen application; do not present a partial ANSI tail as a faithful saved screen. [xterm security guidance](https://xtermjs.org/docs/guides/security/)

### Cleanup, restore and acceptance additions

Retain at most 64 terminal records per project and 256 per instance. Never evict active, queued, unresolved or reservation-owning records to make room. An explicit metadata cleanup removes only terminal records whose exact runner retirement and reservation settlement are confirmed; expired output is independently eligible. Reserve a bounded termination record with at most three deliberate attempt aliases per admitted terminal, reusing the same target identity after a failed attempt; exact retries work at ordinary capacity. After exhaustion, leave explicit administrator recovery instead of accepting unlimited new aliases. Termination cannot be reported complete while the launcher or database cannot establish absence and settlement.

Extend P009's installed module registry with terminal metadata, retained output and private project-quota directories. Checkpoints must drain or explicitly interrupt terminals and confirm all descendants retired. Restore preserves visible history, expired output/gaps and original uncertainty, invalidates controller/input authority, and marks processes stopped; it must not launch a PTY, contact a source-host runtime or replay pending bytes. Compatible promotion drains terminals or shows the consequence of interrupting them before replacing their supervisor.

Extend the six acceptance cases with actual no-account pinned PTY readiness and delayed exit beyond the ordinary RPC timeout; Local and derived Git workspace mounts; browser close and API-only restart while a real shell emits output; two controllers/takeover/stale frames; duplicate/lost input acknowledgements without duplicate bytes; expiry behind locks and queued control denial; database loss before/after input dispatch; output retention and snapshot race; split UTF-8/ANSI payloads, hostile OSC/HTML/links and replay-generated input suppression; slow readers/floods; shell exit with a surviving background process; all queued/live/retained/input/output limits; and P003/P004/P007 typed-reservation conflicts. The supported Linux lane must exercise the actual launcher, pinned PTY and negative filesystem/network/privilege probes. A native PTY which needs no model key can be verified without claiming a live model turn; any account-dependent operation added later retains its separate live gate.

Design review: an independent agent checked runtime separation, authority, typed reservations, input ambiguity, replay and restore. One Medium clarification added a nonempty input requirement, separate pending-row cap and numeric frame/control rates so zero-byte traffic cannot evade byte quotas. These bounded corrections preserve scope; implementation and actual PTY/Linux evidence remain pending.
