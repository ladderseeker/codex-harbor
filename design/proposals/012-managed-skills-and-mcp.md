# P012 — Managed skills and MCP

- Decision: Accepted
- Delivery: In progress
- Dependencies: [P003](003-parallel-project-workspaces.md)
- Outcome: The owner configures a trusted skill or MCP service for a project, invokes it in a conversation, and can disable its future use.
- Design updated: 2026-09-08; one independent design review and focused correction check closed under the owner's authorized direction. The pinned account-free capability spike passed; it is not Harbor implementation or Linux/live evidence.

## Scope and supported profiles

The initial matrix contains two local profiles: a skill directory with `SKILL.md` and supporting files, and a self-contained Node.js STDIO MCP bundle with a relative `.mjs`, `.cjs`, or `.js` entrypoint. Dependencies must already be included in the bundle or pinned runner image. Harbor performs no package installation, setup script, marketplace access, remote HTTP connection, OAuth flow, credential injection, or host executable discovery for this feature. These exclusions select an explicitly tested local profile from the original local-or-remote scope. Unsupported configurations receive a visible unsupported result before execution; no desktop plugin or universal MCP compatibility is claimed.

The owner selects a registered source workspace and relative directory, inspects its immutable snapshot, and enables that version for the project. Conversations then use it with their own selected workspace and permissions. Source edits do not alter an enabled version: explicit refresh creates a new snapshot and configuration revision. Skills are selected in the composer; MCP tools have a conversation picker and explicit tool action, as well as model-directed use during an authorized turn. Effective configuration, tool startup/status, safe descriptions and errors remain visible.

P004's editor, P006's terminal, schedules, previews and deployment UI are not prerequisites. P003 can provision the source directory through ordinary approved project work or a fixture. When P008 or P009 is delivered, the shared-grant and backup obligations below apply.

## Owner and API flow

The project Extensions panel lists versions and offers Add skill, Add local MCP, Refresh source, Enable, and Disable. Show source workspace/path, digest, current project revision, enabled/effective state, profile, selected-workspace access, and whether running work would be interrupted. The initial credential reference is `none`; reject credential fields instead of silently ignoring them. Descriptions, filenames, schemas, errors and results are untrusted text: no HTML, remote icons, images, or automatic URL requests.

Add narrow versioned routes for project extension lists/details and durable create/refresh/enable/disable operations, conversation effective configuration/tool discovery, and conversation tool invocation/cancellation. Requests contain registered IDs, expected revisions, relative source paths, supported profile fields and bounded JSON arguments. They cannot carry app-server methods, native paths, commands, shell arguments, environment maps, mount roots, destinations or raw TOML. Extend OpenAPI and the existing operation/event envelope. The timestamped idempotency contract compares the complete normalized request hash.

Configuration and source publication are owner-browser-only, with current owner/session/instance checks, exact Origin and CSRF. P002 tokens gain no implicit configuration/probe access. Existing execute-scoped clients may select registered skills in an ordinary turn under their project/permission ceiling and the same revision checks; direct MCP actions initially remain owner-browser-only. Existing cancellation authority can stop a tool action without a write ceiling. Elicitation answers reuse P001's current approval authority and cannot expand the original permissions.

Source snapshotting is a fixed P003-style metadata operation: commit a stable extension/version ID and validated source identity, reserve the source against managed writers, then perform the bounded copy. This action grants no later execution by itself. Registration leaves a version disabled. Enabling or probing is explicit execution authorization for trusted project code; even requesting a tool list may have effects. Probes name their workspace and run read-only, account-free and network-disabled in a disposable runner. Never probe disabled code automatically on page/list access. Normal tool actions use the conversation's actual permission profile and writer admission, not an MCP annotation's claim of read-only behavior.

The composer selects at most four enabled skill IDs and records the current extension revision in the accepted turn. The server resolves their immutable `SKILL.md` paths into pinned `UserInput.skill` values. An explicit MCP action records server/version/tool identity and JSON arguments, serializes with ordinary conversation work, and displays a separate persisted tool activity. It makes no model request and is not fabricated as an assistant answer or a native history item. Model-directed MCP calls retain their real native item provenance.

## Immutable sources and trusted configuration

The storage service copies only the selected directory beneath the registered workspace, using descriptor-relative traversal and before/after source checks. Reject escaping/absolute paths, `.git` metadata, symlinks, hard-linked input files, special files, invalid UTF-8 paths and identity swaps. Copy into fresh inodes in a root-owned extension directory inside the project's hard quota but outside writable checkouts; preserve no ownership or executable/special mode bits. The manifest records paths, sizes, hashes, source workspace identity and final directory identity. Publication uses stable IDs, exact helper retirement, filesystem durability and command-hash receipts as in D005. A lost result reconciles its original effect instead of snapshotting newer source. Inspection never executes project code in the API, supervisor or storage service.

Limit a snapshot to 16 MiB, 1,024 files, 16 directory levels, 1,024 bytes per path and 4 MiB per file; `SKILL.md` is UTF-8 text of at most 64 KiB. Limit each project to 32 extension records, 16 enabled skills, four enabled MCP servers and 64 MiB of snapshots; instance limits are 256 records and 256 MiB. Admission checks these limits and D003's hard quota. Retain at most four unreferenced historical versions per extension; versions referenced by active/uncertain operations remain pinned and count toward the limit. Refuse further growth rather than deleting referenced evidence. Unused-version removal checks its exact registered identity and never removes source files.

Mount only the selected immutable versions from the conversation's project, read-only at fixed identity-derived paths. Revalidate trusted ancestors, root ownership, device/inode and manifest bytes before mount resolution under D002/D003. No other project's bundles, global owner skill directory, developer home or native credential store is imported. Enabled skill names are unique within the project and validated/bounded; unresolved declared dependencies produce unsupported status, never automatic installation.

For MCP, derive the native server name from its registered ID and use the fixed Node executable with the selected relative entrypoint. Its working directory is the conversation's `/workspace`. Reject caller-defined Node flags, preload/module search paths, inherited host environment, network endpoints and native addon profiles. Fix native startup/tool timeouts at 10/60 seconds. Generate configuration from enabled, hash-validated local profiles only, with unsupported plugin/app/hook/remote extension surfaces disabled. Repository configuration must not add MCP servers or override policy; inspect effective native configuration before dispatch and fail closed on mismatch.

Managed skill selection is explicit: disable the native automatic skill instruction catalog and bundled skill advertisement using pinned fields, and set process extra roots to the enabled immutable versions. Public discovery and input resolution expose only registered enabled IDs. The toggle controls Harbor's managed discovery/dispatch; it is not filesystem access control on the original project text. Authorized code or a model reading project files can still read instructions stored there. Do not claim disabling a skill makes that source unreadable or prevents similar approved project code from running.

MCP executes in the assigned runner with the conversation's existing UID, mount, capability, process, quota and network bounds. Read-only profiles have physically read-only checkout/common mounts; workspace-write profiles hold the existing exclusive writer reservation. Native tool annotations/approval cannot loosen those mounts. D001 permits only the fixed model transport for conversation runners; this feature adds no remote MCP/development egress. Trusted local MCP code may access credentials used by its own native conversation runtime, as qualified in the architecture/D004; it receives no additional service, control-plane, host or other-project secret. Account-free probes receive no model credential.

## Revision, dispatch, disable and recovery

Persist project configuration revisions, extension/version manifests and identities, enabled state, profile/source metadata, effective runtime revisions, durable commands and bounded results. Native configuration files are generated projections, not policy authority. A new/resumed runtime applies and verifies its recorded revision before dispatch. An idle runtime with a different revision is retired exactly, then relaunched against the same native history; do not silently change a loaded generation's policy. Browser or API restart does not relaunch dispatched work.

Every accepted turn, manual tool action and probe captures the extension revision. Recheck current actor and revision after shared lock waits and immediately before external dispatch. A changed revision makes undispatched work visibly stale and requires a new explicit request; it cannot silently gain new tools. Preserve owner gate → actor → project → workspace → conversation/operation lock ordering, with configuration rows under project authority. If P008 exists, its grants capture the extension revision; configuration changes pause affected schedules until preview and grant renewal. Already accepted fixed storage effects may reconcile without authorizing another execution step.

Enable/refresh applies to future generations; active work continues with its recorded revision, visibly distinguished from current settings. Disable first durably removes future admission and invalidates queued dependent work. For a live generation containing the extension, the action explicitly says **Disable and stop affected conversations**, records exact generations and shows the affected count. The supervisor blocks new Harbor dispatch immediately, expires pending elicitation answers, interrupts affected work, and retires exact runners including MCP/background children before reporting `disabled`. Until retirement is confirmed the state is `disabling` or `uncertain`; already running code may finish effects during that interval. An old receipt cannot retire a successor, and no action claims completed effects were undone.

Manual tool actions use the existing durable dispatch lifecycle: intent before native send, exact conversation/generation/operation association, writer ownership until confirmed retirement, and `uncertain` after ambiguous transport or result COMMIT loss. Never replay automatically. Reconciliation may inspect state without reinvoking the tool. Explicit acknowledgement after exact retirement permits new work while preserving original uncertainty/provenance; reuse P007's shared fencing machinery when delivered, without requiring its UI for the minimal P012 recovery flow.

Support pinned `mcpServer/elicitation/request` standard `form` through the existing approval/input surface. Accept a bounded object schema with at most 16 primitive string/number/integer/boolean/enum fields and bounded labels/options/values; no remote references, nested executable schema, URI navigation or credential autofill. Validate the response against the supported schema and current actor/generation before the first answer. First answer wins across tabs. A direct call's nullable native turn ID must map to its exact pending tool operation. The displayed/recorded input deadline is the earlier of P001's five-minute policy cap and the parent tool's remaining 60-second call budget, with five seconds reserved for answer delivery. Do not assume native timeout pauses for input. Track a direct call from its dispatch; a model-call form needs an observed, unambiguous parent tool start and a supported timing contract. If the remaining budget cannot be established, decline the request explicitly. Native timeout/resolution, operation cancellation and generation retirement immediately expire the input, even before its displayed deadline. Unsupported URL/OpenAI-form variants, requests for Harbor/host secrets, excess permissions, stale requests and expiry are declined/cancelled, never auto-approved. Approval adds no filesystem/network authority.

Allow one tool action/probe at a time per conversation, one project probe, and four probes per instance, with a 90-second probe lifetime. Bound discovery to 64 tools/server, 8 KiB per description/schema and 256 KiB aggregate; over-limit catalogs cannot leave partial callable entries. Arguments are at most 32 KiB/depth 16; results at most 256 KiB, plain text/JSON with explicit omission markers and no embedded-resource fetch. Existing runtime line, mailbox, process and native-history bounds remain enforced; malformed/flooding code can trigger exact runner retirement with a visible failure. Retain 128 settled ordinary extension commands/project. Each unresolved extension/generation target separately reserves one disable operation, one cancellation operation and one retirement-acknowledgement operation; one action cannot consume another's slot. Reconcile an exact existing key before any admission/retention check. Additional keys for an existing control return its operation reference without accepting or storing another alias. A failed control retries its same operation with expected-attempt comparison, at most three recorded attempts and three audit outcomes per action; no repeated click creates a fresh record. Exhausted attempts remain visibly unresolved and require exact administrator recovery, never silent reservation release. Tool activity shares conversation history/operation ceilings. Lists use pages of at most 50 with filter-bound five-minute cursors. Operational audit logs contain no bundle bytes, tool arguments or returned secrets.

## Independent acceptance

Use two P003 projects, Local and a derived workspace, synthetic skills with supporting files, a real disposable STDIO MCP service with harmless filesystem/counting tools and form elicitation, and denied/malicious fixtures. Real Harbor UI/API/PostgreSQL/supervisor/storage components exercise the complete flow; only OIDC and the model/protocol boundary may use documented deterministic fixtures. Pinned real-runtime and actual Linux lanes remain distinct evidence.

1. **P012-01:** Discover/configure, snapshot and enable a skill and MCP bundle through the browser. Invoke the skill through a conversation and an explicit tool through its API/UI; assert immutable source/version/effective revision and observable persisted result. Reopen the browser and restart the API without duplicate effects. Exercise a derived workspace against its own selected files.
2. **P012-02:** Switch projects/workspaces, inspect effective tools, race configuration with queued dispatch and authority expiry after lock waits, and exercise supported scoped-token skill selection. Assert no global enablement, cross-project bundle/credential exposure, unauthorized configuration/probe, stale revision dispatch or inherited authority. When P008 exists, configuration changes pause schedules until renewed grants record the new revision.
3. **P012-03:** Submit unsupported connection/credential fields, executable flags, dependencies, schemas, forbidden destinations, source substitutions, oversized bundles/catalogs/results, malicious repository config and excess permissions. Assert denial before installation/connection/dispatch, or bounded visible failure for behavior detectable only after authorized startup. Exercise quota errors and reserved stop/recovery capacity.
4. **P012-04:** Disable pending/active model and manual tool work, including native input waiting. Assert immediate new-admission denial, visible stopping/uncertainty, exact child retirement before disabled/writer release, first-answer/stale-generation checks, and no blind replay after dispatch/result COMMIT loss, process death or restart. With P009, restore extension state disabled and historical operations retired; require destination revalidation and new enablement before execution.
5. **P012-05:** Render hostile descriptions/results/forms on desktop/mobile without scripts, URL fetch, unsafe HTML or credential autofill. Run actual pinned profiles on Linux to verify read-only/write differences, disjoint project/common mounts, immutable bundle authority, host/control-secret and forbidden-network denials, background-child retirement and quota/resource limits. The P009 inventory includes all persistent extension state and excludes disposable probe homes/secrets.
6. **P012-06:** With Codex 0.153.4, load/list/disable the skill, start local MCP, invoke its harmless tool and answer real form elicitation in an account-free contract. Separately use dedicated live credentials for a bounded real skill invocation and model-directed MCP call, with actual effect and approval/input evidence. The account-free spike covers only its listed capabilities; direct calls or synthetic picker entries cannot replace model-backed evidence.
