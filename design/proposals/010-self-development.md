## Scope and owner flow

Register Harbor's source as an ordinary allowed project and select a separate development worktree. Through the running conversation, request a source change, invoke the same development/build/test entry points used locally, inspect candidate results, and prepare an immutable artifact for promotion. A candidate URL is available only through its authenticated private route. Failure can be inspected and cleaned up from stable Harbor or the external recovery path.

The initial self-development workflow does not require the file-editor UI, interactive terminal UI, general preview feature, scheduler, or extension manager. P001's agent execution performs source edits; this feature provides its scoped build/test authority and candidate inspection route. It does not allow a task to edit the running deployment directly.

## Broker and isolation contract

Implement a trusted build/test broker outside coding runners. It accepts only registered worktree/snapshot IDs, a server-owned command profile, and bounded resource requests. Snapshot source before execution and record its digest. Scripts and Dockerfiles remain untrusted input: the broker runs them in restricted build workers, not its privileged process.

The broker provisions the [D008 worker and disposable guest](../decisions/008-isolated-self-development-workers.md), using fixed mount/network/launcher templates. The guest contains actual candidate services, its own native Docker daemon, separate database/role, volumes, Codex home, identity configuration, URL/ports and credentials. The nonroot outer worker container is the host boundary even if the guest and QEMU process are compromised. Candidate supervisor launch authority reaches only disposable guest resources. Names alone are insufficient: enforce resource ownership at the broker/OS boundary and reject stable/other-candidate IDs.

Coding tasks receive no host Docker socket, daemon credentials, arbitrary mount flags, privileged nested Docker, or host-admin token. A short-lived capability may invoke only the assigned test job and inspect its output; it cannot administer deployments or mint broader credentials. Standard command wrappers route supported build/test profiles through this broker in a Harbor runner and use equivalent trusted local provisioning from a developer shell. Upon delivery, this path must work without manually bypassing isolation.

Reserve capacity for stable Harbor, enforce candidate quotas/lifetimes, and clean up by manifest. Candidate tests use synthetic state and external fixtures; real runtime/isolation evidence remains separately required. Promotion references the tested artifact digest/report and follows P009's independent release path and current user authorization. Deployment credentials never enter candidate code; replacing the supervisor drains or explicitly interrupts its active control session.

## User/API, authority and durable jobs

The conversation's Development panel lets the owner enable the fixed command profiles for its Harbor source workspace, see capability expiry, submit a build/check/test, follow bounded logs and phase changes, open an authorized candidate, stop it, and prepare the exact verified artifact for P009. Show source and artifact identities, changed-source conflicts, queued/capacity results, failed checks, expired grants and uncertain retirement. A prepared artifact is distinct from a promoted release; the panel must not label missing live/checkpoint gates as passed. Reconnecting a browser shows the existing job and its log replay floor without resubmitting it.

Add versioned browser routes for development capabilities, job list/detail, submit, cancel, confirmed-retirement acknowledgement, candidate open, artifact metadata/download and release preparation. Mutations use current owner/session/instance authority, exact Origin, CSRF, expected revision/generation and the existing timestamped idempotency/request-hash contract. Capability issuance and job submission require the assigned project and workspace-write ceiling. Stop/read do not require a target write ceiling. Browser-issued development grants are separate from P002 PATs; existing PATs gain no development administration or promotion routes implicitly. P002's current-authority helpers and project ceilings remain shared implementation dependencies.

Runner requests go through D008's narrow gateway and assignment capability, not the browser API cookie. Use 32 random bytes, a purpose-separated stored hash, exact instance/owner/project/workspace/conversation generation, a fixed profile allowlist and expiry no later than two hours or its issuing authority's expiry. Issue at most one active capability per conversation and 16 per instance, at most eight accepted jobs per capability. Replacing one revokes future use of the old value. Never return the raw capability in ordinary APIs/events/logs; the trusted launcher publishes it only to that runner's read-only assignment file. Before any new dispatch, verify the current source authority, live generation and capability after lock waits. An already accepted bounded job may finish after browser logout; current browser authority is still required to inspect it or prepare a release.

The broker accepts only opaque registered source/job/profile IDs and bounded expected metadata. It commits capture intent and resource reservation before filesystem/container effects. Source conflicts produce a failed capture with no build; explicit retry uses a new capture of current bytes. A lost response returns the original job and immutable input. Worker launch/retirement uses a recorded immutable container ID and owned image/mount manifest, never a reusable name alone. A crash after launch but before acknowledgement becomes reconcilable `uncertain`, never an automatic second guest. Existing jobs survive API/browser restart, and broker restart first reconciles exact owned resources before new admission.

Persist jobs, capability hashes/revocation, phase/attempt state, source manifests/digests, artifact digests and compatibility, independent verification outcomes, candidate-view references, log watermarks, control intents and bounded audit outcomes. Preserve owner gate → actor/capability → project → workspace → conversation/job lock ordering. D008 owns the explicit optimistic capture from the requesting writer; ordinary conflicting writers and project metadata reservations still block capture. The copy's immutable manifest is authoritative even if the editable workspace changes later; the UI displays that distinction.

A successful build seals the exact artifact, retires its build worker, and starts a fresh verification worker from the sealed administrator guest base. Trusted fixed tests and report authority outside both guest and outer worker determine pass/fail and bind the report to those exact bytes. The separate confined candidate browser holds only disposable candidate credentials, not stable browser/admin authority. A candidate's own successful exit or forged worker report cannot bypass failed external checks or write the trusted report store. Verification results bind source/artifact, worker/base/policy/dependency digests, required check IDs, environment and timestamps. A later source edit does not mutate an existing result, and artifact substitution invalidates release preparation.

`pnpm dev` requests inspection of that candidate under a unique HTTPS hostname. Reuse D007's one-use browser bootstrap, host-only viewing cookie and current-authority stream checks with a fixed broker-to-guest target, rather than P011's project launcher. P011 need not exist first; common grant/proxy primitives belong in shared modules. Candidate fixture OIDC and Harbor session cookies remain independent of stable cookies. Hostile candidate HTML cannot execute under the stable origin or receive a stable/broker credential. Do not expose guest SSH, QMP, Docker, database or generic forwarding through this route.

## Resource limits, cancellation and recovery

D008 owns the hard worker/host reservations. Application admission allows one executing worker and one queued job per instance; a ready inspection worker still occupies that capacity. Limit stored jobs to 32 per project/128 per instance, source snapshots to 256 MiB/30,000 entries/depth64/16 MiB per file, artifact files to 2 GiB and retained artifact bytes to 8 GiB per instance. The broker verifies an actual Harbor source layout and a pinned frozen lockfile; it does not build an arbitrary host path. Retain at most two unreferenced snapshots/artifacts per project; referenced active or uncertain resources cannot be garbage-collected. Refuse new work when evidence or quota limits prevent safe admission.

Each job has a two-hour total lifetime; bound its startup, command and transfer phases separately within that deadline. Logs retain at most 2 MiB per job for 24 hours, with bounded chunks, explicit truncation/replay floor and safe text rendering. Cap structured reports at 256 KiB; cap list pages at 50 with filter-bound five-minute cursors. Keep at most 32 accepted ordinary command aliases per capability. Reserve separate cancel and retirement-acknowledgement operations for each unresolved job, each reusing its own stable ID with at most three expected-attempt retries and three audit outcomes. Exact-key reconciliation precedes capacity checks; repeated controls do not append aliases or consume the other control's reserve. Unknown cleanup retains capacity and requires the documented exact administrator recovery path.

Cancellation first closes candidate viewing/dispatch, records stopping, retires the exact worker and background children, then marks stopped and cleans only its owned paths. Cancelling a candidate never cancels the stable coding conversation. Late callbacks from a retired worker cannot publish results or affect its successor. A failure during artifact extraction/publication leaves owned staging with no prepared release; recovery verifies exact manifest/digest and either finishes that publication or reports uncertainty, without executing a candidate hook on the host.

P009 backs up durable job/source/artifact/report metadata and the retained release artifacts, with complete module coverage. Disposable guest disks, probe/test homes and candidate credentials are excluded. Restore revokes capabilities/viewer grants, retains historical outcomes and disables every old queued/running job; it never contacts source-host workers or restores their launch authority. P009 promotion consumes only the exact independently verified artifact with compatible schema/native/runtime checks and all required release gates. A checkpoint or migration failure leaves stable admission/state governed by P009, never by a candidate's claimed success.

## Independent acceptance

Use a stable installation of delivered P009 and P002/P003, an isolated immutable snapshot of an actual Harbor repository revision, and real candidate services. Create the editable candidate worktree from that snapshot, apply a controlled test change, and snapshot the resulting source for its recorded build digest. Do not substitute a toy replacement application for Harbor. The deterministic external Codex fixture may script coding actions; the source edits, broker, build, candidate, database, and browser/API tests are real.

2. **P010-02:** Inspect candidate through its authorized browser/API route while the stable conversation continues streaming. Assert distinct state, cookies, ports, database credentials, and runtime homes.
3. **P010-03:** Fail a candidate build/test, crash its services, and exceed candidate resources. Assert stable health/input/cancellation remain usable and failure is visible.
4. **P010-04:** Supply malicious script/Dockerfile, mount/path/namespace arguments, and another candidate's IDs. Assert no stable-secret, host, or cross-candidate access.
5. **P010-05:** Run cleanup and expire a test capability. Assert only owned candidate resources disappear and the capability cannot later mutate either environment.
6. **P010-06:** Prepare a successful artifact, reject a changed/untested artifact, and exercise the P009 promotion/rollback procedure. Assert exact artifact verification and explicit handling of the running development session.
7. **P010-07:** Exercise the same entry points from local development and a compatible Linux host, including real Linux isolation and bounded real-Codex smoke. Assert no manual privilege bypass is required.
