## Scope and user/API flow

Add a workspace file tree, bounded filename/text search, text editor, authenticated downloads, Git status, and code/diff views. Show unsaved edits, stale revisions, unavailable/binary/oversized files, and external changes. Provide explicit stage/unstage and commit actions, with exact selected changes visible before mutation. Each action has an authenticated API equivalent and an observable result.

Changing a file does not automatically stage, commit, push, or publish it. Hosted pull requests, automatic merge conflict resolution, full IDE language services, and browser previews are excluded. User permission and existing session authorization govern requested Git effects; UI selection and server authority must agree.

## Contracts and security

The workspace service owns file operations and uses project-relative paths or opaque file references. Resolve access using the [filesystem boundary](../architecture.md#execution-and-filesystem-isolation), including race-resistant operations and actual mount confinement. File saves carry an expected content revision and fail on a stale revision rather than overwriting newer contents silently.

Revision checks coordinate Harbor editor writes; arbitrary shell writes can still race unless covered by the actual operation's locking/confinement strategy. Use workspace admission for managed Git mutations, structured argv instead of interpolated shell command text, and idempotency for consequential actions. Git hooks are executable project code and must remain in the runner boundary. Record the resulting commit/object identity so uncertain command delivery is reconciled rather than replayed blindly.

Render names, file contents, search results, and diffs as untrusted content. Downloads require current authorization, bounded size, safe content disposition, and no executable application-origin preview. Limit watch/search scope and output volume. Path denial must not leak secret contents through errors.

## Independent acceptance

1. **P004-01:** Navigate and search a workspace, edit/save a text file, reload, and download it. Assert disk bytes, returned revision, and rendered state agree.
2. **P004-02:** Change the file from a second managed client before saving the first client's draft. Assert a conflict with the draft preserved and a deliberate reload/reapply path.
3. **P004-03:** Inspect a diff, stage selected changes, and commit. Assert exactly the selected files/hunks and recorded commit identity; a repeated idempotency key cannot create an additional commit.
4. **P004-04:** Exercise missing, binary, oversized, renamed, and deleted files. Assert clear bounded results, correct watcher invalidation, and no broad filesystem scan.
5. **P004-05:** Attempt unauthorized paths, symlink replacement during access, malicious names/diff text, and unauthenticated downloads. Assert denial or escaped rendering and no control-plane execution/data leak.
6. **P004-06:** Restart the API during a read/save or uncertain Git operation. Assert reconciled outcome/revision, preserved user draft, and no automatic repeated commit; run actual Linux path-isolation probes.

## Recorded implementation design — 7 September 2026

This amendment concretizes the authorized outcome. Delivery remains Planned until the integrated dependency baseline is available; no file/Git endpoint or editor is claimed implemented here. P003’s [D005 decision](../decisions/005-managed-project-workspaces.md) remains the authority for trusted checkout/common mounts, the managed Git profile and workspace writer ownership. The following contracts extend its fixed helper and durable receipt mechanisms rather than granting the API host filesystem or command execution access.

### Workspace view and editor

The project workspace selector opens **Files** and **Changes** for an explicit workspace ID. The visible workspace name/kind and busy/uncertain state remain present beside file paths and Git actions. A lazy directory tree, filename/text search, editor, and change list share this selection. Changing workspaces or closing a dirty editor requires an explicit keep-draft/discard choice; saving never stages anything. Renamed/deleted files leave the draft available with a conflict explanation and a deliberate reload/reapply action. There is no force-save toggle that bypasses revision checking.

Use the direct `monaco-editor` package pinned to **0.56.0**, lazy-loaded from authenticated, locally built assets, without a React wrapper or CDN dependency. Microsoft published that release on 20 July 2026; its website still advertises 0.55.1, so the pin follows the inspected release rather than the stale landing-page version. Use standalone text and diff editors with one bounded model per open file, dispose models/workers on close, and bundle the editor worker through the existing Vite build. Enable accessible labels, automatic layout and keyboard navigation; keep application controls usable on narrow viewports with a single-pane diff option. Disable clickable content links, rich/untrusted hover providers, external schema fetches, project extension loading and automatic formatting. Syntax coloring is presentation only. Full language services remain excluded. [Pinned Microsoft release](https://github.com/microsoft/monaco-editor/releases/tag/v0.56.0), [upstream integration/model guidance](https://github.com/microsoft/monaco-editor/blob/v0.56.0/README.md), [editor options](https://microsoft.github.io/monaco-editor/typedoc/interfaces/editor_editor_api.editor.IStandaloneEditorConstructionOptions.html)

Drafts remain in browser memory by default, never operational logs or persistent browser storage. An API or supervisor restart preserves the open tab and its draft. A browser reload warns about unsaved work; it does not promise recovery of text never saved to Harbor. A lost save response retains the same operation/key and draft until reconciliation, so an uncertain request never silently becomes a new save.

### Public read and invalidation contracts

All routes are under `/api/v1/workspaces/{id}` and resolve the registered workspace and its project before any content or receipt is disclosed. Versioned OpenAPI declares exact route descriptors rather than a permissive prefix. Browser mutations retain Origin/CSRF and current pinned owner checks. P002 extends its explicit scope vocabulary with `files:read`, `files:write`, `git:read`, `git:write`; tokens also require the selected project grant. Both write scopes require the effective workspace-write ceiling. Existing tokens gain no new scopes automatically. File/Git scopes never imply credentials, raw runtime or host administration access. Cookie-free authenticated downloads use an Authorization header through fetch; no token appears in a URL.

| Route | Result or accepted intent |
| --- | --- |
| `GET /files/tree?path=&cursor=&limit=` | One directory page, entry kind/opaque reference, bounded display path, directory revision and explicit truncation |
| `GET /files/search?q=&mode=filename|text&cursor=` | Literal query results, relative path, bounded line/snippet for text mode, scan/truncation budget and filter-bound cursor |
| `GET /files/content?ref=` | UTF-8 text or an explicit binary/oversized/unavailable reason, exact byte revision and file metadata |
| `GET /files/download?ref=&revision=` | Authorized attachment download of the exact inspected revision; changed content returns conflict |
| `POST /files/save` | `{ref, expectedRevision, text}` with Idempotency-Key; durable operation ID/result |
| `GET /git/status?cursor=` | HEAD/ref identity, staged/unstaged/untracked/conflict entries, index revision and bounded page |
| `GET /git/diff?ref=&side=staged|unstaged` | Exact old/new blob identities and modes, bounded diff and selectable server-derived hunk IDs |
| `POST /git/stage`, `POST /git/unstage` | Exact reviewed selection, expected HEAD/index/file revisions and Idempotency-Key |
| `POST /git/commit` | Reviewed staged-tree identity, exact selected entries/hunks, expected HEAD/ref/index, explicit message and Idempotency-Key |
| `GET /file-operations/{operationId}` | Scoped queued/running/succeeded/failed/uncertain result, identities and safe reason; no raw helper log |
| `POST /file-operations/{operationId}/inspect` | Explicit bounded exact-helper retirement and read-only effect inspection, expected reservation epoch and Idempotency-Key |
| `POST /file-operations/{operationId}/release` | Consume a confirmed inspection with explicit unknown-effects acknowledgement; release only its typed ownership CAS |
| `GET /files/events?cursor=` | Authorized bounded invalidation stream with workspace revision and resync marker |

Opaque references encode or map exact relative filename bytes and are bound to workspace identity; they are not filesystem authority. Unicode and hostile names remain navigable without treating display strings as shell syntax. Reject NUL, absolute paths, parent traversal, ambiguous separators, excessive depth and paths into Git administrative/control locations. Symlinks appear as non-traversable entries; neither reads nor writes follow them. Invalid-UTF-8 names receive an escaped display label and opaque reference, not lossy round-tripping. Missing/renamed identity returns a bounded not-found/conflict response without an outside-path diagnostic.

Initial limits are 1 MiB UTF-8 per editor model/save, 4 open models, 16 MiB per download, 200 directory/status entries per page, path depth 32 and 4 KiB encoded path. Search is literal, 1–120 characters, at most 10,000 visited entries/32 MiB inspected text/2 seconds and 200 matches per response; files above 1 MiB are reported as skipped. A signed cursor carries scope/query/directory revision and remaining finite scan budget, expires after five minutes, and cannot turn a bounded query into an unlimited recursive scan. Hidden ordinary files remain discoverable; `.git`, native homes, Harbor staging and other control metadata are always excluded. Git status scans at most 10,000 paths, with an explicit incomplete result; incomplete selection cannot authorize a commit. Diffs are capped at 1 MiB/2,000 hunks/20,000 lines per file and 100 selected paths/2 MiB total selection per mutation. Binary/oversized entries show status and exact identity, support a bounded download where eligible and whole-file selection where the complete byte/object identity is available; they never masquerade as an empty text diff. An exceeded complete-review budget rejects mutation with a named limit.

Watch only the selected workspace's expanded directories/open files, at most 32 directories and four file content revisions per client, with a two-second coalescing interval and no repository-wide recursive watcher. Polling is an acceptable portable backend under those bounds. Notifications invalidate views; they do not replace drafts or claim a lossless audit of external shell writes. At most four streams per actor and 1,000 retained invalidations per workspace for one hour; a missing cursor/gap requires rereading the bounded view. Resync also follows API restart. Every stream and download rechecks current authority; downloads stop on disconnect/revocation, have a 30-second deadline, `attachment` disposition, safe encoded filename, `application/octet-stream`, `nosniff` and `no-store`. HTML/SVG never render on the application origin.

### File revision, admission and durable saves

A file revision binds the workspace identity epoch, exact relative reference, regular-file device/inode, mode and SHA-256 of its exact bytes, with an explicit absent-file marker where creation is supported. Reads use descriptor-relative no-follow opens, require a regular single-link file, and compare metadata before/after hashing. Deny hard-linked editable files rather than allowing an unseen alias to be changed. Preserve UTF-8 bytes, BOM and line endings unless the user explicitly edits them; a no-op save is not a newline conversion. Git administrative files cannot be edited through this route.

A managed save first accepts a durable bounded operation in PostgreSQL, including the expected revision and immutable new-content digest. Its bounded payload is kept only while needed to complete/reconcile that operation, not as a duplicate repository history. The supervisor acquires the same workspace writer exclusion as P003; an active or uncertain runner, unresolved helper, storage operation or recovery holds the workspace busy. Saves never race a Harbor agent writer by merely comparing an earlier hash. Reads may run during a writer, but return an observed revision and honest changed-during-read failure, not a consistency guarantee over an entire tree.

Lock order is current authority/instance gate, project metadata reservation where required, workspace, then related session/operation. Use the shared lock-then-current-clock authority helper after waits and immediately before accepting the fixed effect grant. Expired/revoked callers cannot start a queued save/Git command. A command whose effect grant and private receipt are already committed may finish/reconcile that exact effect after logout; this does not grant any new command or runtime send. Maintenance freezes new file/Git admission and drains accepted effects under D006.

Inside the confined helper, open the validated checkout root and all ancestors by directory descriptors without following links. Recheck the expected target revision after all admission waits, create an exclusive same-directory temporary regular file with safe preserved mode, write and fsync, revalidate the target, then atomically replace it through the held parent descriptor and fsync the directory. Never edit in place or truncate before checking. Parent/target swaps fail or remain confined to the owned descriptor subtree; they cannot redirect access to the host. Arbitrary out-of-band SSH/root writes are outside Harbor reservations: detect observable changes and report them, but do not claim compare-and-swap against an uncooperative external writer that changes the file between the final check and rename. The actual Linux tests must establish confinement separately from managed-client revision serialization.

A trusted receipt outside project roots binds operation ID, actor grant, workspace epoch, expected revision and new digest before the first effect. Record prepared/applied/completed phases and resulting identity, flush the project filesystem before publishing completion on the control filesystem, and follow D005's exact-helper retirement rule. Response/DB commit loss returns the same recorded result. If a crash leaves effect ambiguity, inspect only the recorded destination and owned staging after confirmed helper retirement: an authenticated applied receipt identifies the intended result but is not proof that the effect survived a crash. Revalidate the exact recorded file identity/content and complete the project flush before publishing completion; mismatch stays uncertain without replay. A completed post-barrier receipt can reconcile the original success despite a later external change. Unproven content coincidence does not justify another write. Mark uncertain and retain the writer reservation until explicit inspection/acknowledgement, with no automatic overwrite replay. The retained operation is readable after API restart.

### Exact Git selection and publication

A status/diff review token binds the registered checkout/common identities, HEAD symbolic target and object ID (or unborn marker), complete index digest/tree and exact old/new path/blob/mode identities. Server-derived hunk IDs hash that versioned diff plus hunk offsets/content. Stage/unstage accepts only IDs from the reviewed generation; no client-supplied patch, revision expression, refspec, arbitrary Git option or shell command is accepted. Recompute the selected diff under reservation before applying. A changed index, HEAD, selected file, rename pair or hunk returns 409 and preserves the UI selection/draft for explicit refresh; do not silently widen to all changes.

Stage applies selected unstaged whole files or text hunks to the index only. Unstage applies selected staged whole files or hunks toward HEAD in the index only, preserving worktree bytes. The UI distinguishes staged and unstaged sides and shows excluded changes. Rename pairs, binary data and mode changes are indivisible whole-file selections; conflicted index entries are visible but cannot be staged/committed through this feature until deliberately resolved externally. Use a private temporary index constructed from the validated current index and exact server-generated patch/blob updates, then validate the result tree. Git's own index lock plus the Harbor workspace/project reservation prevents other managed publishers; stale external index changes reject before publication. Never call reset/checkout/clean as a substitute for unstage. [Git apply index semantics](https://git-scm.com/docs/git-apply)

Commit previews the complete staged tree and its difference from the expected parent, including selected hunks. It commits exactly that reviewed staged tree: if unrelated staged entries exist, the owner must include them explicitly in the complete review or unstage them first. No implicit `-a`, hidden staging, amend, merge, signing, push or remote action occurs. A partially staged file retains its unstaged changes. Require a nonempty message up to 8 KiB and configured validated author name/email; show the identity before acceptance. Do not import untrusted repository identity or executable signing configuration. Unborn HEAD is supported with a no-parent tree and explicit absent-ref expectation; detached HEAD is visibly identified and uses an exact HEAD publication target.

The confined helper creates the exact commit object from the reviewed tree, parent, message, identity and acceptance timestamp fixed in the durable intent. Persist the resulting commit OID in the trusted receipt before advancing the branch/HEAD. Publication uses a fixed validated ref and old-OID comparison, retaining the branch identity check; do not accept a ref supplied by the browser. Reconciliation checks the recorded object and exact ref result after confirmed helper retirement. A receipt proving publication returns the original OID even if a later external change moved the branch; otherwise conflicting/unknown publication stays uncertain and never creates another commit or resets the ref. Git objects, index/ref durability and project flush must complete before the external completion receipt. An applied Git receipt predates the final project barrier: revalidate the recorded index, ref and required tree/commit/blob objects, then flush successfully before promoting it to completed. If recorded applied state is missing or conflicts, retain uncertainty without replaying an index/ref write; only a completed post-barrier receipt proves the original success independently of later edits. Interrupted stage/unstage similarly reconcile the recorded old/new index digest, never reapply an uncertain patch. [Git commit-tree](https://git-scm.com/docs/git-commit-tree), [old-value ref update](https://git-scm.com/docs/git-update-ref)

Local Git publication uses the Local checkout's authoritative in-checkout `.git` index, objects and refs. P003's imported project `git-common` is an independent store and is never a substitute target for a Local stage/commit. The confined helper reaches Local metadata through no-follow descriptor-relative authority within the validated checkout and its sanitized metadata view; a repository-controlled `.git` pathname is never elevated into host bind-mount authority. Derived Git workspaces instead publish through the registered common repository and their validated workspace administrative IDs. Status/diff/review tokens explicitly bind which of these stores is authoritative, preventing cross-store index/ref publication. Unsupported external Local gitdir/commondir mappings fail closed under D005.

All Git operations remain inside D005's fixed nonroot, network-disabled helper with immutable entrypoint, resource limits and selected checkout/common mounts. Extend its action enum and protocol; do not add a generic exec route or host Git call. Disable hooks, filters, textconv, fsmonitor, external diff, pagers, automatic maintenance, signing, credential helpers and all network protocols. Local/common configuration is never executed or imported into the sanitized metadata view. Git hooks are not run by this managed profile, and the commit UI states that fact; a future hook-execution feature would need an explicit confined execution contract. Raw objects are hashed/staged without project clean/smudge filters, with that managed-profile limitation visible. Unsupported alternate/object/gitdir/submodule configurations fail closed rather than expanding mount access.

Any mutation of shared common Git metadata holds P003's project metadata exclusion in addition to its workspace writer reservation, and conflicts with existing managed writers that can access that common store. This may serialize Git publication across otherwise independent worktrees; it does not stop independent read-only inspection or alter their source checkouts. A pending/uncertain file/Git operation also blocks workspace deletion, source copy/import and explicit release until its exact helper is confirmed retired. P007 recovery must not release another operation's reservation; use typed ownership/epoch CAS rather than treating every writer as a conversation.

### Resolve an uncertain file/Git reservation

An uncertain operation exposes **Inspect and fence this file/Git operation**, followed only after a confirmed result by **Acknowledge unknown effects and release workspace**. These actions do not use the conversation-recovery endpoint. `POST /file-operations/{operationId}/inspect` requires `{expectedEpoch}` and a timestamped Idempotency-Key; an explicit retry includes `{inspectionId, expectedAttempt, expectedEpoch}`. Only that operation's unresolved typed reservation is eligible. A durable inspection record retains at most three deliberate attempts, each with its own reserved intent alias; exact-key reconciliation precedes changed-state admission. Concurrent distinct attempts conflict, and exhaustion remains visibly blocked for administrator recovery rather than enabling unlimited retries.

Under current authority → project/common → workspace → operation lock order, the supervisor rechecks the exact operation/epoch, confirms immutable owned helper retirement and advances its fence before bounded read-only inspection of the recorded file/index/ref/object and trusted receipt. It never launches the original mutation or infers completion from matching bytes alone. Return a bounded report distinguishing an authenticated completed receipt, observed old/new/conflicting state, missing evidence and unknown durability. Any unconfirmed retirement or failed ownership CAS keeps the typed reservation and marks inspection failed. Database loss retains settlement repair; restart cannot silently turn a pending inspection into release.

`POST /file-operations/{operationId}/release` requires `{inspectionId, expectedEpoch, acknowledgeUnknownEffects:true}` and a new key. The caller reviews the report and retained file/index/ref state first. In one ownership-locked transaction require the successful current inspection/fence and exact typed operation owner, acknowledge the unresolved outcome without relabeling it successful, then CAS-release that reservation and consume the inspection. Original uncertainty, trusted result/receipt and provenance remain readable. No file overwrite, patch, ref update or old command replay occurs; a later edit/Git action needs fresh current revisions and an entirely new operation. A stale/two-tab request returns 409; the exact accepted key still returns its original release result after response loss/restart.

Both browser and authenticated API clients can use this bounded flow with the original operation's project grant plus `files:write` or `git:write` and workspace-write ceiling; current owner-browser authority can recover a revoked creator's abandoned operation. The inspection accepts no arbitrary target or helper ID. Reserve three inspection aliases and one release alias, one inspection record, and at most four audits of 512 bytes with every admitted file/Git mutation; unrelated metadata or ordinary command quota cannot consume that allowance. Reports are at most 16 KiB and use existing bounded native/project content inspection, never a repository copy. Unresolved records are never GC'd to make room. P003 deletion/release and P007 recovery must recognize this reservation type and reject it rather than clearing its owner. D006 maintenance may invoke its fixed administrator equivalent only with the same exact retirement and recorded acknowledgement rules; backup itself never performs the acknowledgement.

### Bounded persistence and acceptance additions

Add an additive P004 migration for file/Git operations, typed workspace reservation ownership, safe result/revision metadata and invalidation cursors. Bound retained file/Git operation receipts to 128 per workspace and 4,096 per instance, with at most four queued commands per workspace and four executing helpers per instance. Refuse new mutations before allocating payload/staging at quota. Existing-key reconciliation and exact-owned cleanup remain available at capacity; expired-key rejection follows P002's retention window. Do not evict unresolved receipts or expand capacity through new retry aliases. Terminal payload bytes are erased after confirmed receipt/result retention; unresolved payloads count toward a 16 MiB per-workspace/64 MiB per-instance control staging quota. Logical limits supplement D003's kernel quota and separate control headroom.

The P004 module registry includes operation/receipt metadata and only owned pending payload/staging; files, index/objects/refs remain in the complete P003 project quota unit. D006 checkpoints must settle accepted effects or fail backup explicitly. Fresh-host restore preserves uncertain history while revoking old effect/retry authority; it must not execute source-host receipts. An older binary that cannot honor the new writer type cannot run against the upgraded active database; rollout/rollback uses the recorded compatibility and backup rules.

Keep P004-01–06 unchanged and extend their fixtures with partial staging plus unrelated staged/unstaged content, exact repeat/response-loss commit identity, two-client revision conflict, index/HEAD change between review and admission, queued-grant expiry/revocation, parent/hardlink/symlink replacement, hostile Git configuration/hooks/filters, search/download limits, invalidation resync, API/supervisor/helper loss before and after index/ref publication, and database commit failure after filesystem success. Assert zero host execution/network, exact selected disk/index/tree bytes and OIDs, retained draft and uncertainty, no second effect, and only owned cleanup. Test Local Git metadata and derived Git workspaces sharing their imported common store with actual Linux helper mounts, including typed reservation conflicts with P003/P007. This design neither narrows the six acceptance outcomes nor establishes their implementation evidence.
